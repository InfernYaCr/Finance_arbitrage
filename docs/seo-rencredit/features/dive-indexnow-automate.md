## 1. Реальность: API, лимиты, библиотеки

| Что | Статус | Факты |
|---|---|---|
| Яндекс IndexNow `POST https://yandex.com/indexnow` | живой | До 10 000 URL в одном POST. Ключ от 8 до 128 символов `[A-Za-z0-9-]`, файл `<key>.txt` в корне, содержимое файла равно ключу. Число запросов не ограничено. Один и тот же URL чаще раза в 10 минут слать не просят. Коды ответа: **200** ключ проверен и URL приняты; **202** ключ новый, ждёт проверки, «подождите и отправьте снова»; 403 ключ не загрузился или не подходит; 422 невалидные параметры; 429 слишком много запросов с одного IP. Источник: https://yandex.ru/support/webmaster/ru/indexnow/reference |
| Обмен между поисковиками | да | Отправка в любой эндпоинт расходится по всем участникам: Bing, Yandex, Seznam, Naver, Yep, Amazon. Google в протоколе не участвует. Совет: слать только при значимых изменениях. https://www.indexnow.org/faq |
| `velohost/astro-indexnow` 2.3.10 | живой, MIT, 15★, push 2026-07-08 | Astro 4–7, хэширует HTML и шлёт только изменённые страницы. **Не брать**: пинг идёт на этапе `astro build`, то есть **до** выкладки. | Лицензии и юридическое | — | Протокол открытый, ключ не секрет: он и так публикуется файлом на сайте. Персональных данных нет, поэтому 152-ФЗ не затрагивается. Рекламы нет, 38-ФЗ тоже. Финсоветов нет |

Проверка по текущему `dist`, собранному 17.10 как прод (`robots: index, follow`):
- В sitemap 83 `<loc>`, на живом сайте тоже 83.
- Скрипт соберёт **69** URL: 213 `index.html` минус 144 `/go/*`. **14 легаси-статей `/credit/<slug>.html` не попадут**, а это ровно те страницы, у которых есть возраст и тематический сигнал (`07` §D5).
- Noindex-страниц вне `/go/` сейчас нет, кроме `404.html`. Но фильтр `isEmptySvcPage` (`astro.config.mjs:42-50`) может закрыть пустые сервисные посадочные. Скрипт про это не знает, sitemap знает.

**Ошибка в аудите `07-yandex-domain-history.md` §D5 и `10-content-factory.md` п.4.** Там сказано, что `:50` срезает завершающий слэш и отправляются URL без него. Это неверно: `:52` дописывает слэш обратно (`${SITE}${path}/`). Реальных багов три: пропуск `.html`, 202 как успех, отправка всего сайта вместо изменённого.

**Ошибка в карточке идеи.** Предложено хранить `dist/.indexnow-hashes.json`. Так не выйдет: `astro build` очищает `dist` перед каждой сборкой, и состояние будет стираться. Хранить его надо вне `dist`.

Совместимость: на сайт ничего не добавляется. Сетевой шаг выполняется на машине, с которой идёт деплой (Node 22 уже есть, `fetch` встроенный). Вес JS на клиенте 0. PHP и хостинг не участвуют, нужен только статический `.txt` в корне.

## 3. Ценность

- **Индексация.** У сайта только что сменилась тема (рефинансирование → МФО). `07` оценивает первичную переиндексацию 83 URL в 1–3 недели. IndexNow ставит URL в очередь обхода сразу после выкладки, но включения в выдачу не гарантирует. Статус «малоценная» он тоже не снимает.
- **Где это действительно важно:**
  - новости о регулировании, например `novosti/mfo-limit-psk-200-s-1-oktyabrya-2026`. Запросы вида «лимит ПСК МФО с 1 октября 2026» и «ключевая ставка решение ЦБ октябрь» живут несколько дней, и опоздание на 3–5 дней с обходом съедает весь пик. Честно: у СМИ в такой выдаче преимущество, наш шанс в длинном хвосте («как новый лимит ПСК влияет на займ до зарплаты»);
  - 14 переписанных `/credit/*.html`: старые URL с новым контентом, нужен быстрый переобход;
  - обновлённые условия офферов (ставки, суммы). Это YMYL: устаревшая цифра в сниппете хуже, чем отсутствие сниппета.
- **ПФ и ссылки.** Напрямую не влияет. Косвенно даёт свежий сниппет, который совпадает со страницей, и меньше отказов из-за расхождения цифр.
- **Монетизация.** Трафик на новые страницы с офферами приходит на несколько дней раньше. Сумма в рублях при текущем трафике околонулевая. Это гигиена, а не драйвер роста.
- **Bing и Seznam** получают пинг бесплатно через обмен.

## 4. MVP (0,5 дня)

1. **Ключ.** `openssl rand -hex 16`, затем файл `web/apps/rencredit/public/<key>.txt` с этим ключом внутри. Коммитить (ключ не секрет).
2. **`scripts/indexnow.mjs`.** Переписать сбор URL и добавить guard, около 40 строк вместо обхода `index.html`:
   - **Источник URL** — `dist/sitemap-0.xml` (regex по `<loc>`). Сразу получаем `.html`-легаси, без `/go/`, без noindex-посадочных, ровно канонические адреса. Файл для хэша: `/` → `index.html`, `/x/` → `x/index.html`, `*.html` как есть.
   - **Guard хоста:** origin из sitemap должен совпадать с `INDEXNOW_SITE || 'https://rencredit-online.ru'`. **Guard noindex:** если в `dist/robots.txt` есть строка `Disallow: /` (`robots.txt.ts:8`), пропускаем. Оба признака берутся из собранного артефакта, а не из env, так что тестовую сборку не отправим даже по ошибке в `.env`.
   - **Ключ:** env `INDEXNOW_KEY`, иначе файл `dist/*.txt`, у которого содержимое совпадает с именем. Тогда `.env.deploy` ничего не нужно.
   - **Дифф:** sha1 HTML после вырезания `/_astro/[^"' )]+`, чтобы правка CSS не помечала изменёнными все 83 страницы. Состояние хранится в `web/.indexnow-state.json` (`{url: sha1}`), одна строка в `web/.gitignore`. Отправляются новые и изменённые URL. Удалённые только выводятся в лог: деплой файлы не удаляет, на сервере они по-прежнему отдают 200, и слать их бессмысленно.
   - **Ответы:** 200 → сохранить состояние. 202 → «ключ на проверке», состояние **не сохранять**, чтобы следующий деплой отправил ещё раз. Остальные коды → stderr и выход с кодом 1. Флаг `--all` принудительно шлёт весь sitemap.
3. **`scripts/deploy-beget.sh`.** Перед `exit 0` на `:110` и `:160`:
   ```bash
   if [[ "$MODE" == deploy ]]; then node "$ROOT/scripts/indexnow.mjs" || echo "⚠ IndexNow не отправлен (деплой при этом прошёл)"; fi
   ```
   Деплой из-за IndexNow не падает. Шаг выполняется только после успешной заливки (`set -e`).
4. **`docs/DEPLOY.md:122`.** Вместо «по желанию» написать: «автоматически; `--all` — вручную».
5. **Проверка.** `curl https://rencredit-online.ru/<key>.txt` отдаёт ключ. Первый деплой вернёт 202, второй (через 10+ минут или со следующей выкладкой) 200. В Вебмастере «Индексирование → Статистика обхода» видно обход отправленных URL в течение суток. Самопроверка в скрипте `node scripts/indexnow.mjs --dry` печатает список и решение guard без сети. Её можно сделать единственным тестом.

## 5. Полная версия (ещё 0,5–1 день, по мере надобности)

- **CI.** В `deploy-rencredit.yml` убрать input `indexnow`, оставить шаг безусловным после mirror и добавить `actions/cache` на `web/.indexnow-state.json`. Без кэша CI каждый раз отправляет все 83 URL. При таком размере это допустимо, поэтому кэш можно не делать. Отдельно: в том же workflow FTP без TLS (`ftp:ssl-allow no`), см. `10` п.44. Это не про IndexNow, но чинить там же.
- **Новостной контур.** Цепочка `news-data-automation.md:125` (build → deploy → indexnow) получается сама собой: публикация новости приводит к деплою, а скрипт находит новый URL по диффу. Отдельный код не нужен.
- **`lastmod` в sitemap.** В аудите это есть (`07` §D5, R3), здесь не дублируется. Вместе с IndexNow это даёт Яндексу два согласованных сигнала свежести. Нельзя бампать `lastmod` и HTML без изменения содержания (`10` п.3): дифф по sha1 и так защищает от холостых пингов, но не от искусственных правок даты.
- **Не делать:** API Вебмастера «переобход» (квота маленькая, нужен OAuth, IndexNow закрывает ту же задачу), отдельный пинг Bing (идёт через обмен), `astro-indexnow` (причины в п.1).

## 6. Риски

| Риск | Мера |
|---|---|
| Пинг с тестового поддомена или noindex-сборки | guard по `robots.txt` в `dist` плюс сверка origin с прод-хостом |
| 202 считается успехом, первый пинг теряется | не сохранять состояние на 202, повтор при следующем деплое |
| Дифф стирается вместе с `dist` | состояние вне `dist`, в `web/.indexnow-state.json` |
| Смена CSS или года в футере (`Footer.astro:11`) помечает изменёнными все страницы | вырезаем `/_astro/*`. Год меняется раз в год, 83 URL один раз допустимы |
| Деплой с другой машины или из CI без состояния | отправит весь sitemap. При 83 URL это безвредно |
| Двойная работа с SEO-треком | это R3 из `07`. Закрывать одним PR, в `07` поправить пункт про слэш |
