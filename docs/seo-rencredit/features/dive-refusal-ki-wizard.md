# Deep-dive: мастер «Почему отказали» и «Кредитная история бесплатно и самозапрет»

Идея `refusal-ki-wizard` для rencredit-online.ru (бренд «Мерка»), Astro 7 static. Дата: 2026-10-19.
Основа: finhelp-adapt-1 §10, finhelp-adapt-2 §9, refinance-legacy R5. Каждый пункт я перепроверил по коду воркдерева `/Users/deniskononov/rencredit-pilot-wt` и по живому сайту.

**Вердикт: do_next, 6.5/10.** MVP займёт 2 дня, и почти всё это время уйдёт на контент, а не на код. Делать стоит, но в урезанном виде. В исходной идее три лишние вещи: общий «движок квиза», localStorage и генератор заявления в БКИ. Реальная ценность — восстановить старый кластер «отказали в рефинансировании» на прежних URL и закрыть пробел по кредитной истории. Прямая монетизация слабая: после отказа люди конвертируются хуже всех. Две вещи в исходной идее неверны: «ссылки проверяет `check-links.mjs`» и «Кредо — сверить». Подробности в §1.

**Ссылки Госуслуг.** Из этой сети `gosuslugi.ru` не отвечает: curl отдаёт 000, это геоблок или таймаут. Сайты бюро отвечают: nbki.ru 200, bki-okb.ru 200, scoring.ru 200, credistory.ru 200. Сайты creditinfo, spectrum и t-bki тоже вернули 000. Отсюда две проблемы:
- `web/scripts/check-links.mjs` проверяет **только внутренние** `href="/..."` (регулярка `\s(?:href|src)=["'](\/[^"'\s]*)`), внешние ссылки он не трогает. Тезис идеи «ссылки проверяет check-links» неверен.
- Проверять внешние ссылки на CI вне РФ бессмысленно. Решение: держать все внешние URL в одном `bki.json` с полем `checked: "YYYY-MM-DD"`, раз в квартал проверять их руками из РФ. На Госуслуги ставить ссылку на **главную** с подсказкой «в поиске наберите „Сведения о бюро кредитных историй“», а не на глубокий ID услуги: ID меняются.

**Лицензии и лимиты:** не применимо. Сторонних библиотек нет, запросов к API нет.

## 2. Что есть в коде и куда встраивать

**Уже есть:**
- `src/scripts/home-logic.ts`: `type Ki = 'good' | 'none' | 'bad'`, `KI_LABELS`, `KI_FEATURE = { bad: 'bad_history' }`. Главная читает `?ki=bad` (`home-picker.ts`). Это пригодится для ссылки из результата: `/?ki=bad`.
- Витрина (`src/scripts/offers-ui.ts:60-80`) читает `?sum`, `?term`, `?age`, `?f=a,b`, `?sort`. Значит, ссылка из результата вида `/zaimy-s-plohoj-ki/?age=19` отдаст отфильтрованную выдачу, и писать ничего не нужно.
- Гайды `/zaimy-s-plohoj-ki/` и `/zaimy-bez-otkaza/` живые (200).
- Статьи `samozapret-na-kredity.mdx` и `kak-uluchshit-kreditnuyu-istoriyu.mdx` живые, `category` у них `fingramotnost` и `kreditnaya-istoriya`. Новости про самозапрет и ПСК 200% есть.
- `legacyUrl` + `src/pages/credit/[slug].astro`: статья с `legacyUrl: https://rencredit-online.ru/credit/<slug>.html` собирается **на старом адресе без редиректа** (`.htaccess`). Так уже восстановлено 14 статей. Это главный рычаг для кластера отказов (§3).
- Метрика грузится только после согласия (`BaseLayout.astro:90-130`, CookieBar), вебвизор выключен (`webvisor: false`). **Ни одного `reachGoal` в коде пока нет**: цели вводит `dive-cpa-click-goals.md`.
- `ArticleView.astro:57`: `<Content components={{ h2: CtaH2 }} />`. MDX-статьи сейчас ничего не импортируют, но импорт `.astro`-компонента в `.mdx` штатно поддерживается `@astrojs/mdx`, а его `<script>` бандлится только на страницах, где компонент есть.
- `ClientRouter`: инициализация на `astro:page-load` через единый `main.ts`. Мастер подключается так же, с guard `dataset.ready`, как `initHomePicker`.

**Чего нет:**
- Мастеров и квизов нет вообще. `CtaPicker` — только чипы суммы.
- `/refinansirovanie/` отдаёт **404** (хаб R2 ещё не сделан). `/credit/otkazali-v-refinansirovanii-osnovnye-prichiny.html` тоже 404.
- Тестов в `web/` нет (`*.test.*` = 0).

**Конфликт с текущей маршрутизацией.** `src/lib/cta.ts:12,23`: категория `kreditnaya-istoriya` ведёт CTA на МФО (`/zaimy-s-plohoj-ki/`). Это расходится с `05-keyword-gap.md:25`, где ядро rencredit — рефинансирование, кредиты, карты и КИ, а МФО вторичны. Мастер должен вести в первую очередь на карты, кредиты и рефинансирование, а в МФО только в ветке «займ», и никогда при ПДН > 50% или 2+ дорогих займах. Это совпадает с `ymyl-content` и `dive-refi-hub.md:70`. Менять сам `cta.ts` в этой задаче не нужно, это отдельное решение.

**Совместимость:** полная. Чистая статика, без PHP и сервера, Astro 7 SSG. Мастер — нативные `<form>`, `<fieldset>` и `<input type="radio">`. Без JS работает статичная таблица «причина → что делать» внутри статьи, и её видит робот.

**Вес JS.** Сейчас `dist/_astro/*.js` весит около 136 КБ, из них GSAP 70 КБ. Мастеру GSAP не нужен. Оценка: правила ~2–3 КБ и логика ~2 КБ, итого около 5 КБ до gzip и около 2 КБ после. Грузится только на 1–3 страницах с мастером.

### Упрощения против исходной идеи

| В идее | Что делаю | Почему |
|---|---|---|
| «Один движок квиза» на два мастера | **Не делаю.** «Мастер КИ» — это линейный чек-лист из 5 шагов, ему квиз не нужен: хватит `<ol>` с `<details>` в MDX, 0 строк JS. Квиз нужен только для «почему отказали». | одна реализация вместо абстракции на два случая |
| Пошаговый wizard на 6–8 экранов | Одна форма, все вопросы на экране, результат пересчитывается на `change`. На мобильном это 8 компактных групп радиокнопок. | быстрее для пользователя, вдвое меньше кода, нет навигации «назад/вперёд» |
| Состояние в `#hash` | Оставить: `#r=<8 цифр>` через `history.replaceState`, без новых записей в history. Даёт ссылку «поделиться результатом» за ~5 строк. | дёшево и полезно |
| Прогресс в localStorage | **Не в MVP.** Для одноразовой диагностики это лишнее. Нужно только чек-листу КИ, если появятся галочки. | YAGNI |
| Генератор заявления об ошибке в БКИ | **Во второй версии.** Для него нужны ФИО, паспорт и реквизиты записи, это отдельная форма и печать. В MVP хватит ссылки на форму оспаривания на сайте каждого бюро: у НБКИ, ОКБ и Скоринга она онлайн. | основная работа, а пользы в MVP мало |
| Цели `wizard_step{n}` | Одна цель `refusal_diag` с параметром `level` (`ok`/`fix`/`stop`) + `ki_step` на раскрытие шагов чек-листа. **Ответы в Метрику не передавать** (см. §3, 152-ФЗ). | меньше шума |

**Старый кластер.** Это 6–7 legacy-URL отказов: `otkazali-v-refinansirovanii-osnovnye-prichiny`, `top-6-prichin-pochemy-banki-otkazyvaut-v-refinansirovanii`, `sberbank-otkazal-v-refinansirovanii-prichiny-kak-ispravit-sityaciu`, `pochemy-bank-otkazyvaet-v-refinansirovanii-posle-restryktyrizacii`, `prichiny-otkaza-v-refinansirovanii-kotorye-skryvaut-banki`, `osnovnye-prichiny-pochemy-bank-ne-refinansiryet-kredit-daje-pod-zalog`. Сейчас все отдают 404. Судьбу остальных URL (301 на эту статью или на хаб) решает SEO-аудит `07-yandex-domain-history.md:153`, я её не дублирую. Мастер даёт этой статье то, чего нет в выдаче: я не нашёл ни одного русскоязычного анонимного теста «почему отказали». Банки.ру и Сравни продают кредитный рейтинг с персональными данными, остальное — текстовые статьи.

**Поведенческие факторы.** Форма из 8 вопросов — это 30–60 секунд взаимодействия, плюс 1–3 перехода по плану: статья о КИ, самозапрет, витрина. Реальных данных нет, оценку в процентах не даю. Цель `refusal_diag` даст их через 2–4 недели после запуска.

**Ссылкоёмкость.** Низкая или средняя. Финфорумы и Пикабу ссылаются на «вот проверь, почему отказали» чаще, чем на статьи, но разовый мастер ссылочного не соберёт. Чек-лист КИ без персональных данных цитируемее.

**Монетизация (честно).** Слабая и косвенная.
- Отказник — худший лид: у него ниже одобрение, а CPA платит за выдачу. Ветки «стоп» (ПДН > 50%, 2+ займа с ПСК > 200%, просрочка сейчас, самозапрет) по правилам `ymyl-content` **вообще без МФО**. Там остаются реструктуризация, самозапрет и в будущем ББанкрот (R7, нужен `kind: debt_relief`).
- Ветка «исправимо»: кредитные карты (выплаты 1 250–4 500 ₽), рефинансирование (Т-Банк 5 000 ₽, Альфа 1 750 ₽, из `dive-refi-hub.md`), и только для займов — `/zaimy-s-plohoj-ki/?age=N`.
- Реальная ценность — трафик кластера и сигнал «сайт помогает, а не толкает в долг» для YMYL и E-E-A-T.

### Юридические риски

- **38-ФЗ ст. 28 и запреты ymyl-content.** Никаких «шанс одобрения 87%», «одобрят», «без отказа». Результат формулировать как «вероятные причины по типовым требованиям банков и МФО». `approvalPct` в схеме опционален, у верифицированных офферов его нет (`kotozaim.json`: «процент одобрения официально не заявлен — поля удалены»), а значит, показывать нечего. Офферы в результате выводить через существующий `OfferCard`/`CtaTop3` с `AdMark` и erid, ссылки только `/go/<poolId>/` с `rel="sponsored nofollow"`.
- **152-ФЗ.** Ответы (просрочки, ПДН, самозапрет) — это сведения о финансовом положении. Пока они остаются в браузере и не связаны с идентификатором, оператором сайт не становится. **Нельзя** передавать ответы в Метрику (параметры цели + `_ym_uid` = связка с идентификатором) и писать их в query-string: он попадает в логи Beget и в Referer. Поэтому состояние держим в `#hash`, он на сервер не уходит, а в цель отправляем только агрегатный `level`. Поля будущего генератора заявления (ФИО, паспорт): `autocomplete="off"`, никуда не сохранять, только печать. Вебвизор уже выключен, но и при включении поля нужно маскировать.
- **Финсоветы.** Кредитный совет не лицензируется (39-ФЗ касается ценных бумаг). Риск здесь репутационный и YMYL. Нужен дисклеймер «ориентир, не гарантия и не консультация; решение принимает кредитор; банк вправе отказать без объяснения причин».
- **Самозапрет и мошенники.** В ветке «самозапрет» повторить предупреждение из статьи: оформлять только самому на Госуслугах или в МФЦ, ссылки из СМС не открывать.
- **Устаревание.** Список БКИ, даты законов и МПЛ меняются раз в квартал. Факты держать в одном JSON с датой `checked` и выводить её «Проверено: …».

## 4. MVP (2 дня) и полная версия

### MVP

**Код (~0,5 дня):**

1. `src/data/refusal-rules.ts`: чистые данные и функция без DOM, по образцу `home-logic.ts`, чтобы её можно было вызвать и в SSR, и на клиенте.
   ```ts
   export type Goal = 'mfo' | 'credit' | 'refi';
   export interface Answers { goal: Goal; overdue: 0|1|2; active: 0|1|2; ban: 0|1; pdn: 0|1|2; age: 0|1|2; psk200: 0|1; restr: 0|1; young: 0|1; income: 0|1 }
   // ponytail: эвристика на 10 правилах, без весов и ML; веса — только если появятся данные по целям
   export const RULES: { id: string; level: 'stop'|'fix'|'ok'; when: (a: Answers) => boolean; reason: string; fix: string; links: string[] }[] = [
     { id: 'ban',    level: 'stop', when: a => a.ban === 1, reason: 'Установлен самозапрет: кредитор обязан отказать.', fix: 'Снять на Госуслугах (УКЭП) или в МФЦ, вступает в силу на 2-й день.', links: ['/stati/kak-snyat-samozapret-na-kredit/'] },
     { id: 'psk200', level: 'stop', when: a => a.goal === 'mfo' && a.psk200 === 1, reason: 'С 01.10.2026 МФО не выдаёт займ с ПСК > 200% при двух таких непогашенных.', fix: 'Погасить один из займов; не открывать новый.', links: ['/novosti/mfo-limit-psk-200-s-1-oktyabrya-2026/'] },
     // overdue=2 (просрочка сейчас) → stop; overdue=1 (была за 12 мес) → fix; pdn=2 (>80%) → stop; pdn=1 (50–80%) → fix;
     // goal=refi && young → fix «кредит младше 3–6 мес.»; restr → fix; income=0 && goal!=='mfo' → fix; age=0 (18–20) && goal!=='mfo' → fix «у банков часто от 20–21»;
     // active=2 (5+ займов/кредитов) → fix; ни одно не сработало → ok «скоринг/данные анкеты: проверьте КИ на ошибки».
   ];
   export const diagnose = (a: Answers) => { const hit = RULES.filter(r => r.when(a)); return { level: hit.some(r => r.level==='stop') ? 'stop' : hit.length ? 'fix' : 'ok', hit }; };
   ```
   Ссылки на гайды и витрины по `level` и `goal`: при `stop` — только статьи; при `fix`/`ok` по `goal` — `/karty/`, `/kredity/`, `/zaimy-s-plohoj-ki/?age=N`, а `refi` — на `/refinansirovanie/`, когда появится хаб R2. До этого — на статью `refinansirovanie-kreditov-s-plohoi-kreditnoi-istoriei-perechen-bankov`.

2. `src/components/RefusalWizard.astro`: SSR-разметка из 9 `<fieldset>` с `<legend>` и radio, плюс `<output aria-live="polite">`. В `<script>` около 40 строк: на `change` собрать `FormData`, вызвать `diagnose`, отрисовать причины через `textContent` (не `innerHTML`), записать `#r=…` через `replaceState`, при загрузке восстановить состояние из hash. Цель: `window.ym?.(id,'reachGoal','refusal_diag',{level})` один раз за сессию страницы. Номер счётчика — из `data-` атрибута: `ENV.metrikaId` уже есть в `lib/ui/site.ts`. Init на `astro:page-load` с guard. Стили — существующие токены и классы `chip`, `btn`, `cta-*` из `BRAND.md`/`global.css`, новых зависимостей нет.
