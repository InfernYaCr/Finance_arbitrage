## Топ-11 для rencredit

### 1. Атрибуция CPA-кликов: цели Метрики + placement/subid в /go/ + серверный лог go.php — high / S
**Сейчас:** клик по офферу не виден ни в Метрике (на странице `/go/` нет счётчика, `trackLinks` внутренние ссылки не считает), ни в Saleads по блокам (UTM одинаковые).
**MVP-0, полдня, без PHP.**
- На CTA добавить `?p=<placement>`: hero, showcase, top3, sticky, aside, article и так далее. Компоненты `cta/*` и `OfferCard` уже разделены по местам на странице.
- В `/go/[offer].astro` inline-скрипт дописывает `utm_content=p` и `utm_term=<random subid>`.
- В `main.ts` один делегированный обработчик клика по `a[href^="/go/"]` вызывает `ym(id,'reachGoal','go_click',{offer,p,path})`.

**MVP-1, около дня.** Генератор `go.php` на этапе сборки по образцу dive go-php-click-tracker. В `go.php` вшит белый список id → URL из пула. 302 с `X-Robots-Tag: noindex`. CSV-лог с `flock` вне docroot. IP не пишем, UA храним как усечённый хеш. Правило в `.htaccess`: `^go/([a-z0-9-]+)/?$`.

Почему это важно: Метрика здесь работает только после согласия, а серверный лог считает все клики без персональных данных. Это единственный способ получить EPC по страницам и слотам.
**Риск:** деплой — `tar -x` без удаления. Старые `dist/go/*/index.html` останутся на сервере, и nginx может отдать их до rewrite. Нужен деплой с `--archive-old` или ручная чистка. PHP на хостинге: старый WP работал, но перед переключением прогнать smoke-тест 302 по всем id.

### 2. «В реестре ЦБ на <дату>» + проверка МФО по реестру + автоскрытие исключённых — high / S–M
**Сейчас:** номер реестра есть у всех офферов, но выводится только текстом. Футер и калькулятор утверждают «все — из реестра ЦБ», и это ничем не подтверждено.
**MVP.**
- Скрипт сборки или `sync-pool.mjs` раз в неделю качает `list_MFO.xlsx` и сохраняет `cbr-registry.json`: номер, ОГРН, имя, вид, дата исключения.
- Сборка падает или скрывает оффер, если МФО-номера нет в реестре.
- На обзоре показывается бейдж «В госреестре МФО · проверено 19.10.2026» со ссылкой на cbr.ru/finmarkets.
- Виджет «Проверить МФО» встраивается в существующую статью `kak-proverit-mfo-v-reestre-cb.mdx`: поиск по ~1 тыс. записей в статическом JSON, сверка с `warning-list` («признаки нелегального кредитора»).

Это повышает доверие (E-E-A-T, YMYL) и даёт интерактив на странице с запросом «проверить мфо в реестре».
**Риски:** структура xlsx у ЦБ меняется, поэтому колонки нужно искать по заголовку, а не по позиции. Для банков (`kind` card/credit) номер — это регномер лицензии, проверять его нужно по CreditOrgInfo, а не по list_MFO. Короткие номера вроде «30» или «963» нельзя сверять поиском подстроки.

### 3. Калькулятор-проверка ПСК: «ваш займ в пределах закона?» — high / M
Основа — dive psk-legal-checker (score 8), адаптированный под rencredit:
- Данные: `14082026_mfo.xlsx` и `_ko.xlsx`, поквартальный `psk_limits.json`.
- `psk.ts`: решатель ПСК бисекцией по ч. 2–2.3 ст. 6 353-ФЗ. Тест-векторы из dive: 30 тыс. ₽ / 30 дней / 37 200 ₽ → 292,000%; со страховкой 1 500 ₽ → 371,404%.
- Флаги: 0,8% в день, переплата 100%, «ПСК в договоре не совпадает с расчётом по платежам». Новый флаг для rencredit: «ПСК выше 200%: с 1.10.2026 МФО не выдаёт такой займ, если у вас уже два таких займа». Он опирается на новость сайта `mfo-limit-psk-200-s-1-oktyabrya-2026.md`.
- Где разместить: страница `/kalkulyator-psk/` и встраивание в статью `chto-takoe-psk-i-kak-ee-schitat.mdx`.
- Под результатом — офферы с `pskMax ≤ 200`, из 29 офферов с ПСК, через `filterProducts`.
- Формулировка вердикта: «по нашему расчёту превышает», без слова «незаконно».

**Срок:** выпустить до ~14.11.2026, пока не вышли данные ЦБ за следующий квартал.

### 7. Личный слой «Мои МФО»: «Одобрили?», «вы здесь уже брали», недавно смотрели — medium-high / S
Основа — dive mfo-client-personal-layer. Блокер «нет витрины» на rencredit снят.
