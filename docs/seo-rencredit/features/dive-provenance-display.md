# Deep-dive: «Откуда цифры» (provenance-display) — rencredit-online.ru

Дата проверки: 2026-10-19. Код: `/Users/deniskononov/rencredit-pilot-wt/web/apps/rencredit` (Astro 7, статика). Живой сайт проверен curl. SEO-аудит `0*.md` не повторяю. Пересечения: п. 9 в `06-eeat-legal-trademark.md` (страница `/metodologiya/`) и C3 в `competitor-features.md`. Этот документ уточняет C3 по реальным данным.

## Вердикт

**do_now, MVP 1,5 дня.** Фича дешёвая, без JS и без зависимостей, а данные уже лежат в репозитории. Но в исходном виде показывать их нельзя: проверка нашла три проблемы, которые сноски сразу вытащат на страницу (§2.3). Поэтому в MVP входит чистка данных и проверка ссылок, а не только вёрстка. Журнал изменений (`history[]`, «Что менялось», RSS) — **later**: сейчас он пустой, потому что все 33 файла сверены один раз, 13.10.2026. Первые реальные изменения появятся при обязательной пересверке до 12.11.2026 (через 30 дней сборка начнёт падать). Тогда журнал и стоит делать.

Прямой трафик от фичи измерить не получится. Она работает через доверие: асессоры YMYL, AI-ответы и конверсия кнопки. Брать её стоит потому, что она стоит ~1,5 дня и ни у одного конкурента такого нет (`competitor-features.md`, матрица §2).

Что из этого следует:
- Документы МФО живут недолго (пример — `red-051026`). Битая ссылка на «первоисточник» хуже, чем отсутствие ссылки. Проверка ссылок обязательна.
- Автоматическая проверка по статусу даёт ложные срабатывания на 401/403/000. Падать нужно только на 404/410. На остальное выдавать предупреждение, не прятать ссылку и не писать «пересверяем».
- Внешних API для MVP не нужно. Реестр ЦБ (`cbr.ru/finorg/foinfo/?ogrn=`) — обычная страница, ссылки на неё уже в данных. Лицензий и лимитов здесь нет. Wayback `available` API ответил 429, так что в конвейер его не ставлю.

## 2. Куда встраивается (код)

### 2.1 Что есть сейчас

- `src/lib/offers.ts:20-21` — `import.meta.glob` по `offer-sources`, тип `{ officialUrl?: string }`. Из данных берётся только `officialUrl`, его использует `AdMark.astro:17`.
- `src/pages/[dir]/[slug].astro` (119 строк, страница обзора для `/mfo|karty|kredity/<slug>/`):
  - `rows: [string, string][]` (строки 44–54) — таблица «Условия», рендер `<dl class="dl">` (строка 90);
  - `legal` (строки 55–58) — «Юридические данные»: организация и номер в реестре, **без ссылки на ЦБ и без даты**;
  - `note-card` (строки 106–108): `'Условия сверены с сайтом организации.'` — на живом `/mfo/denga/` эта фраза есть, но без даты и источника.
- `OfferCard.astro:53` — для `!verified` уже выводится «Условия по данным организации, не сверены редакцией.». Для сверенных ничего не выводится.
- `web/scripts/check-content.mjs:15-38` — `verified=true` требует `fields.<k>.url` на каждое числовое поле, `checkedAt` ≤ 30 дней и `cbrLicense === registry.regNumber`. Схема данных уже защищена, и новая проверка для неё не нужна.
- `popover`, RSS, `@astrojs/rss` в коде нет. CSS для `.dl` и `.note-card` есть в `src/styles/global.css:442-454`.

### 2.2 Совместимость

- Статика Astro 7: всё считается на сборке. **0 КБ JS.** Хостинг не важен, PHP не нужен.
- Дату показываем **только абсолютной** («Проверено 13 октября 2026»). Вариант «N дней назад» на статике устаревает между сборками и начинает врать.
- Нативный `popover` к 10.2026 уже Baseline widely available, но для MVP я его **не беру**. Лучше видимый список сносок под таблицей: его видят краулеры Яндекса и AI-ботов, он не зависит от позиционирования на мобиле и не нужно ничего нажимать. Popover можно добавить потом поверх списка, если сноски будут мешать дизайну.

### 2.3 Что вылезет при выводе (проверить до релиза)

1. **В `quote` попадают комментарии редакции.** В 41 записи из 315 цитата содержит пометки в скобках, многоточия-склейки и пересказ формы. Например:
   - `tbank-credit.amountMin`: «Форма заявки на странице карты: «…» (minLimit 15000)»;
   - `denga.ageMax`: «возраст от 18 лет (верхняя граница в Правилах не установлена)»;
   - `dengi-srazu.rateDayPct`: «…197,1 процентов годовых (197,1/365 = 0,54% в день)» — это **расчёт редакции**, а не цитата.

   Если показать такое в «ёлочках» как цитату из документа, получится искажённая цитата, то есть ровно тот риск, о котором предупреждает идея. Нужно добавить в схему необязательное `note` и вынести туда всё, что не дословно из документа. Это одноразовая ручная правка ~41 записи по скиллу `ymyl-content`.
2. **`ageMax: 100` — заглушка для «верхней границы нет».** Она стоит у 12 офферов (alfa-kredit-nalichnymi, alfa-refinansirovanie, otp-120, credit7, nebus, denga, prostoy-vopros, ligamfo, dengi-na-dom, rublion, berezhnyy и др.). На живом сайте выводится «21–100 лет». Сноска рядом покажет «верхняя граница не установлена», и противоречие станет видно. Это отдельный мелкий баг (его уже отметил `05-keyword-gap.md`, стр. 116). Чинится в `lib/format.ts`: при `ageMax >= 100` выводить «от N лет». Это надо сделать в том же PR.
3. **`dengi-srazu` — все источники 404.** До релиза его нужно пересверить или временно поставить `verified: false`.
4. **`notes` — внутренняя кухня.** Там CAPTCHA, «Firecrawl 401», агрегаторы. **Никогда не рендерить.** В тип glob включаем только `checkedAt`, `registry`, `fields`.
5. **38-ФЗ.** Сноски выводим только для строк, которые реально показаны. Цитата про ставку («0% годовых», «0,8% в день») не должна появиться, если `showsRate(o) === false` или строка «Ставка» не выводится (у карт её нет). Иначе ставка окажется на странице без ПСК (ч. 3 ст. 28). Список строится из `rows`, поэтому выполняется само собой, если привязать ключи полей к строкам.

## 3. Ценность

**Запросы.** Сноски ставятся на страницы, которые ранжируются по брендовым коммерческим запросам «<МФО/банк> условия / процентная ставка / ПСК / отзывы». Это видно по title обзора (`{name}: условия, ставка, как получить`). В `05-keyword-gap.md` по таким хвостам высокий спрос: «рефинансирование в Т-Банке: условия, ставка, отзывы», «кредитная карта 120 дней без процентов: подводные камни». Новых запросов фича не добавляет. Она усиливает ответ на «условия» на 26 сверенных обзорах без нового текста.

**SEO / E-E-A-T.** Это YMYL. Каждая цифра с документом и датой проверки — то, что асессор ищет в разделе «достоверность». Цитата с номером пункта («п. 18: Полная стоимость микрозаймов…») удобна для извлечения в AI-ответах (Нейро, Алиса). Эффект косвенный, и отдельно его не измерить. Скорее всего, он проявится как устойчивость обзоров на апдейтах, а не как рост.

**ПФ.** Небольшой плюс к времени на странице. Главное — меньше возвратов на выдачу с целью «проверить у кого-то ещё».

**Ссылкоёмкость.** Низкая. На обзор оффера сами по себе не ссылаются. Если что-то и будет, то от журнала изменений («Мерка» заметила, что МФО X снизила ПСК) — это шаг 2.

**Монетизация.** Косвенная: доверие к кнопке «Получить деньги» на обзоре. Идею «автоматически поднимать офферы из блока „Изменилось к лучшему“» **не беру**. Порядок по CPA-приоритету и так спорный (`06-eeat` п. 9). Если смешать редакционный сигнал с сортировкой, методика станет непрозрачной.

**Юридически.**
- 38-ФЗ: см. §2.3 п. 5. Сноски в рекламе не мешают. «Реклама» и рекламодатель уже есть в `AdMark` на обзоре.
- Цитирование документов кредитора — короткие фрагменты в информационных целях со ссылкой на источник (ст. 1274 ГК). Дословность обязательна (§2.3 п. 1).
- 152-ФЗ не затронут: персональных данных нет, в реестре юрлица.
- Финсоветы: фича ничего не советует, она только показывает источник.
- Формулировка «Проверено» — это обещание. На странице нужно сказать, что именно проверено («условия сверены с документами организации 13.10.2026»), и сохранить уже существующую оговорку «окончательные условия определяет кредитор».

## 5. Полная версия (+2–3 дня, после первой пересверки, до 12.11.2026)

1. **`history[]` в offer-sources.** Скрипт `web/scripts/offer-history.mjs` сравнивает `value` и `quote` каждого поля с предыдущей версией файла и дописывает `{date, field, from, to, url}`. Предыдущую версию берёт из копии `offer-sources.prev/` или из коммита, который передаётся аргументом. Пересверка уже проходит через агента и скилл `ymyl-content`, так что отдельной автоматики, которая сама ходит по сайтам МФО, не нужно (антибот, CAPTCHA, см. `notes` у vivus).
2. **Блок «Что менялось» на обзоре.** Показывать последние 3–5 записей с датой и ссылкой на документ. Пустой блок не показывать.
3. **Новости и RSS.** Значимые изменения (ПСК, ставка, 0%) передавать в `content/news` черновиком через скилл `news-pipeline`, а не автопубликацией. RSS делается в рамках E9 (`brand-engagement.md`). Отдельный RSS под эту фичу не нужен.
4. **Служебные страницы.** Те же сноски — на 50 `service-sources/*.json` (структура та же: `fields.<Название>.{value,url,quote}`). Но отдельных страниц обзора у услуг нет, поэтому сноски пойдут только в карточку. Ценность ниже, делать после офферов.
5. Опционально: `lastReviewed` в JSON-LD страницы — одна строка в `ld` (при обёртке в `WebPage`). Для расширенных сниппетов не используется, ценность низкая.
6. Связать со страницей `/metodologiya/` (`06-eeat` п. 9): «как мы сверяем условия» плюс ссылка из блока «Источники условий».
