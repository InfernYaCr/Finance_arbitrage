# finhelp-adapt-1: идеи finhelp ideas[0..59], адаптированные под rencredit-online.ru («Мерка»)

Дата: 2026-10-19. Линза: перенос и перепроверка идей finhelp-ru (Astro 4, донорский датасет) на rencredit
(Astro 7 + Tailwind 4 + MDX, контент-коллекции, `@pbn/core`). Сам SEO-аудит (`docs/seo-rencredit/0*.md`) здесь не повторяю.
Фокус: фичи, механики, интеграции, вовлечение, поведенческие факторы.

Источники: `finhelp_ideas.json` (ideas 0–59 + dives), `docs/seo/features/*.md`, код
`/Users/deniskononov/rencredit-pilot-wt/web/apps/rencredit`, живой сайт (curl), эндпоинты ЦБ/ФНС (curl 19.10.2026).

## 1. Состояние rencredit: что снимает блокеры finhelp

Большая часть блокеров из finhelp-дайвов здесь уже снята:

| Блокер finhelp | rencredit на 19.10.2026 |
|---|---|
| OfferCard мёртв, у офферов нет данных | 33 оффера в `src/content/offers` (22 МФО, 7 карт, 4 кредита). У всех 33 есть `erid`, `legalName`, `cbrLicense`, у 29 есть `pskMax`. Zod-схема роняет сборку при ошибке в данных |
| Нет erid/маркировки | `AdMark.astro` выводит «Реклама · юрлицо · erid», `/go/[offer].astro` передаёт erid в UTM |
| Нет consent-баннера | `CookieBar` есть, Метрика грузится только после согласия (localStorage `fk-consent`) |
| Нет ПСК (ч. 3 ст. 28 38-ФЗ) | `pskRange`/`showsRate`: без ПСК ставку не показываем |
| Квиз-подбор | Уже есть: `home/HomeHero` + `scripts/home-picker.ts`. Сумма, срок, КИ (good/none/bad) → топ-3 с GSAP Flip |
| Фильтры витрины в URL | Уже есть: `offers-ui.ts` (state из URL, чипы, сортировка, «показать ещё») |
| Поиск | Уже есть `search.json.ts` (подборки, разделы, обзоры, статьи) |
| AI-сводка офферов (idea 54) | По сути уже сделана: `summary`, `pros`, `cons`, `verified` в JSON офферов |

Чего нет:

- **Ни одной цели Метрики** (`reachGoal` в `src/` не встречается).
- `/go/<id>/` — статичный meta-refresh без лога кликов.
- **Нет ни одного инструмента или калькулятора**, кроме калькулятора займа на главной. `/kalkulyator/` и `/klyuchevaya-stavka/` отдают 404, в sitemap 83 URL.
- Нет отзывов и опросов. Нет RSS.

Профиль контента: 13 из 22 статей и старые `/credit/*.html` посвящены **рефинансированию**. Есть
`chto-takoe-psk`, `kak-proverit-mfo-v-reestre-cb`, `samozapret-na-kredity`, `chto-budet-pri-prosrochke-zajma`,
`kak-ne-popast-v-dolgovuyu-yamu`. Ниже инструменты, которые прямо продолжают эти статьи.

Хостинг: Beget (nginx → Apache, PHP есть). `scripts/deploy-beget.sh` заливает `dist` без удаления файлов на сервере и
требует `dist/.htaccess`. Значит, `go.php` и `*.php`-эндпоинты возможны.

## 3. Топ-12 идей для rencredit

Порядок — по соотношению эффекта и усилий. Нумерация finhelp указана в скобках.

### 1. Цели Метрики + `go.php`-кликтрекер (finhelp: dive go-php-click-tracker, calc-offer-bridge) — high / M
**Что.** Сейчас нет ни одной цели, поэтому эффект любой фичи не измерить. Это фундамент для всех остальных идей.
- Маленький `lib/ui/track.ts`: `goal(name, params)` → `window.ym?.(id, 'reachGoal', name, params)`. До согласия ничего не
  отправляем, Метрики просто нет.
- Делегированный клик по `a[href^="/go/"]` → `offer_click {offer, placement, page}`. `placement` берём из `data-placement`,
  который уже можно проставить в `CtaSlot`, `CtaTop3`, `OfferCard`.
- `go.php` генерируется при сборке (Astro endpoint или post-build hook по образцу `legacyHtmlFiles`). Внутри — белый список
  `id → outboundUrl` из `@pbn/core`, 302, `X-Robots-Tag: noindex`, subid = `random_bytes` → `utm_term`, лог CSV вне docroot
  (время, id, subid, path, placement), без IP. Правило в `.htaccess`: `^go/([a-z0-9-]+)/?$ go.php?o=$1`. Meta-refresh-страницы
  остаются fallback'ом для `astro preview`.
- Сверка с Saleads `GET /api/v1/click` — позже.

**Риск.** В finhelp не подтвердили, отдаёт ли Saleads `/click` построчно по utm_term. `deploy-beget.sh` не удаляет старые
`/go/<id>/index.html`, а Apache отдаёт каталог раньше rewrite, поэтому правило надо ставить с `RewriteCond %{REQUEST_FILENAME} !-f`
или удалить каталоги вручную.

### 2. Автопроверка МФО по реестру ЦБ + бейдж «В реестре ЦБ с ДД.ММ.ГГГГ» (28, 21, 48) — high / S
**Что.** На `/mfo/<slug>/` уже есть строка «Номер в реестре ЦБ РФ», но она вписана вручную. Нужно:
- скрипт `web/scripts/sync-cbr.mjs` (рядом с `sync-pool.mjs`). Node без зависимостей: zip читается через `zlib.inflateRawSync` и
  разбор central directory, около 40 строк. Пишет `packages/core/src/data/cbr_registry.json` {regNo → вид, дата внесения, ИНН, ОГРН, сайты};
- `check-content.mjs`: если `cbrLicense` оффера нет в реестре, сборка падает, а оффер получает `enabled=false`. Нельзя
  рекламировать исключённую МФО;
- в обзоре и карточке: «МКК · в реестре с 12.03.2021 · проверено 19.10.2026 · [карточка на cbr.ru](/finorg/foinfo/?ogrn=)».

**Проверено:** все 22 номера совпали, ручной маппинг не нужен (в finhelp не нашли 17 из 31).
**SEO.** E-E-A-T и YMYL-доверие на коммерческих страницах. Фраза «Все организации — из реестра ЦБ РФ» в калькуляторе
перестаёт быть голословной.

### 3. Индикатор «Жалобы в ЦБ» по ренкингу Банка России (1) — high / S
**Что.** Ренкинг МФО по обоснованным жалобам на 100 тыс. договоров (13.07.2026, за 2025 год). Сопоставление идёт по ИНН,
ИНН берём из `cbr_registry.json` идеи 2. Выводим блок на `/mfo/<slug>/`: место, группа (крупные / прочие), значение и
дословную оговорку ЦБ. Отдельная страница `/mfo/zhaloby-v-cb/` — рейтинг наших МФО и ссылка на первоисточник.

**Ценность.** Независимый внешний сигнал вместо `rating` (у 0 из 33 офферов он заполнен, и правильно).
**Риск.** Если сменится вёрстка, парсер должен падать, а не выкладывать пустой блок. МФО без ренкинга (малые МКК) получают «нет в ренкинге».

### 4. Калькулятор рефинансирования «Сколько сэкономлю» (адаптация 18/46/26 под профиль rencredit) — high / M
**Что.** На rencredit больше всего контента про рефинансирование, а инструмента нет. Пользователь вводит остаток, ставку,
оставшийся срок и новую ставку или срок. Выход: старый и новый платёж, экономия, точка безубыточности с учётом страховки
и комиссии, SVG-график. Под результатом — офферы `alfa-refinansirovanie` и `tbank-refinansirovanie` с ПСК и AdMark.
Кнопку «рефинансировать сейчас или ждать ставку» из finhelp **не** берём: это финсовет и прогноз (так решено в дайве key-rate-hub).

**Реализация.** `src/lib/finance.ts` (аннуитет, график, экономия) + `node --test` с эталонами из дайва calc-engine-revive
(10 845,72 / 66 780 ₽). Страница `src/pages/kalkulyator-refinansirovaniya.astro`: SSR-результат по дефолтам, состояние в `#hash`,
кнопка «скопировать ссылку». Встраиваем виджетом во все 13 статей и `/credit/*.html` про рефинансирование через MDX-компонент.
Цели: `calc_input`, `calc_result`, `offer_click{placement:calc}`.

### 5. «Проверь свою ПСК» + страница «Предельная ПСК на IV кв. 2026» (20, 47, 42 + dive psk-legal-checker) — high / M
**Что.** Готовый MVP из дайва: решатель ПСК по 353-ФЗ ст. 6 бисекцией (~4 КБ JS), три режима ввода, вердикт
«в пределах / выше среднерыночной / выше предельной», флаги 0,8%/день и переплата 100%. Новое для rencredit — флаг
**«ПСК > 200%»** со ссылкой на нашу новость: если таких займов уже 2+, до 01.04.2027 МФО новый не выдаст.
`psk_limits.json` раз в квартал собирается из `14082026_mfo.xlsx` тем же zip-парсером, что в идее 2.

**Связки.** Статья `chto-takoe-psk` (встраиваем виджет), новость о 200%, обзоры МФО: «ПСК оффера от X% — предел для категории Y%».
**Риск.** Формулировки только «по нашему расчёту», без «незаконно». Раз в квартал нужна ручная сверка xlsx.

### 6. Хаб «Ключевая ставка ЦБ» + плашка + налог на вклады (10, 36, 44, 49, 51 + dive key-rate-hub) — high / M
**Что.** `/klyuchevaya-stavka/`: ставка 14,00% «действует с», дата следующего заседания (сверить), SVG-график из KeyRateXML
(рисуется при сборке), таблица решений, FAQ. Плашка `KeyRatePulse.astro` без JS в хабах `/kredity/`, `/vklady/` и статьях про
рефинансирование. Внутри хаба — калькулятор налога на проценты по вкладам: необлагаемый лимит = 1 млн ₽ × максимальная
ключевая на 1-е число месяцев года; перед публикацией сверить ст. 214.2 НК. Пик запросов — ноябрь–декабрь, поэтому
`/vklady/` получает и инструмент, и трафик.

**Реализация.** `web/scripts/sync-cbr.mjs` (тот же, что в идее 2) пишет `facts.json` + `facts.override.json` на день решения.
После каждого заседания — новость через skill `news-pipeline`, ссылка на хаб.
**Риск.** Каждое решение требует пересборки и деплоя. Почасовой PHP-cron из finhelp-41 избыточен.

### 7. ПДН-калькулятор + ветка «антиспираль» (16, 22) — high / M
**Что.** Список долгов и доход → ПДН с порогами ЦБ → план «лавина / снежный ком». Результат ветвится:
- ПДН до 50% → рефинансирование (офферы);
- ПДН выше 50% или «2+ займа с ПСК > 200%» → **без витрины МФО**: самозапрет, реструктуризация, банкротство через МФЦ.

Статьи для второй ветки берём готовыми из finhelp (`finhelp_articles_reuse.tsv`): `bankrotstvo-cherez-mfc`,
`posledstviya-bankrotstva`, `chto-budet-esli-ne-platit-mikrozajm`, `kollektory-chto-mogut-po-zakonu`. Портировать их в
`src/content/articles` с категорией `fingramotnost` и прогнать skill `ymyl-content`.

**Ценность.** Ответственное кредитование и сильный YMYL-сигнал. Переход в «дорогие» МФО-офферы человек в спирали всё равно
не конвертирует. Пересекается с статьёй `kak-ne-popast-v-dolgovuyu-yamu`.
**Риск.** Реклама банкротства — тоже финреклама. Без давления, вариант МФЦ упоминаем обязательно.

### 8. Калькулятор займа и просрочки + «напомнить о дате возврата» (.ics) (9, 18, 19) — medium / M
**Что.** Отдельный `/kalkulyator-zajma/`: сумма, срок, ставка в день, `freeDays`, сценарий «просрочил на N дней» (неустойка
до 20% годовых, потолок переплаты 100%). После расчёта — кнопка «Добавить дату возврата в календарь». Это `.ics` Blob примерно
в 30 строк (RFC 5545, VALARM за 3 дня, в описании ссылка обратно) плюс ссылка-шаблон Google Calendar. Возвратные визиты дают
поведенческий фактор, человек меньше просрочивает, а значит меньше негатива к МФО и сайту.

**Реализация.** Переиспользовать `home-logic.ts` (`quote`, `overText`) и `finance.ts` из идеи 4. Виджет встраивается в
`chto-budet-pri-prosrochke-zajma` и guides `zaimy-s-prosrochkami` / `dolgosrochnye-zaimy`. Библиотека `ics` не нужна.
**Риск.** Перед публикацией сверить 353-ФЗ ст. 5–6.2 (исключения из потолка).

### 9. «Проверить МФО или сайт займа» по реестру и чёрному списку ЦБ (29, 40, 48) — medium / M
**Что.** `/proverka-mfo/`: одно поле для названия, ИНН/ОГРН или домена. Ответ: в реестре или нет, в чёрном списке или нет
(дословное поле Sign + дата), совпадает ли домен с официальным (детект клонов). После «нет в реестре» показываем
«легальные альтернативы» с офферами. Это интерактивное продолжение статьи `kak-proverit-mfo-v-reestre-cb`.

**Реализация.** При сборке из реестра и black-list-json (10,9 МБ) строим `public/data/trust-index.json` — только нормализованные
домены, ИНН и имена, около 250 КБ gzip. Подгружается лениво после первого ввода, поиск на vanilla JS. Ежедневный cron на Beget —
только если индекс начнёт заметно устаревать. Программные страницы под 27 тыс. нелегалов **не** делаем: тонкий контент и
риск претензий.

### 10. Мастер «Кредитная история бесплатно + самозапрет» (33) — medium / S
**Что.** Четыре шага в `<details>`: Госуслуги → ЦККИ → бесплатные отчёты БКИ (2 в год) → заявление об ошибке
(генерируется в браузере) → поставить или снять самозапрет. Прогресс хранится в localStorage. Статичная страница плюс ~30
строк JS, данные о БКИ — в JSON. Связки: `samozapret-na-kredity`, `kak-uluchshit-kreditnuyu-istoriyu`, guide
`zaimy-s-plohoj-ki`. Из finhelp портируем `kak-proverit-kreditnuyu-istoriyu-cherez-gosuslugi` и `kak-snyat-samozapret-na-kredit`.
Цель `wizard_step{n}` даёт глубину просмотра.
**Риск.** Ссылки Госуслуг меняются — проверять при каждой сборке через `check-links.mjs`, он уже есть.

### 11. «Материал помог? / Нашли ошибку?» на статьях и обзорах (6) — medium / S
**Что.** Две кнопки и необязательное поле «что устарело» внизу `ArticleView` и `/mfo/<slug>/`. MVP без сервера: только цель
`page_feedback{v:yes|no, slug}` в Метрику, отчёт берём из Метрики. Поле текста — через `feedback.php` (honeypot, лимит,
CSV вне docroot) вторым шагом. Метка «Обновлено после замечания читателя, дата» выводится по `updatedDate`.
**Ценность.** Очередь актуализации для YMYL (лимиты ПСК меняются по кварталам) и видимый сигнал свежести.

### 12. Персональный слой: «я уже брал здесь», «недавно смотрели», «сравнить выбранные» (8, 15 + dive mfo-client-personal-layer) — medium / S–M
**Что.** Всё в localStorage (try/catch), ~80 строк:
- автоотметка «переходил» при клике на `/go/`;
- через 1–30 дней — плашка «Получили займ в X? Да / Отказали / Не оформлял», ответ уходит в цели;
- в витрине эти МФО опускаются ниже (не скрываются), у остальных бейдж «вы здесь ещё не брали». Saleads чаще платит
  только за нового клиента;
- «недавно смотрели» на главной и 404;
- чекбокс «сравнить» на карточках → `CompareTable` (уже есть, сейчас только на главной) на `/sravnenie/?ids=` с noindex.

**Риск.** Обещание «первый заём 0% для вас» не делаем: флаг описывает оффер, а не человека. При 3+ отметках «брал» —
показываем блок «антиспираль» из идеи 7.

## 4. Не взятые из ideas[0..59] — почему

- **0 ugc-cleanup** — на rencredit нет донорских виджетов отзывов и фейковых цифр, `rating` не заполнен. Делать нечего.
- **2, 5, 7 отзывы, ответ компании, комментарии** — нужна модерация и PHP+SQLite, а трафика пока нет. Вернуться после 3–6
  месяцев индексации. Опрос «Одобрили?» (**3**) — тоже после этого, когда наберётся выборка от 30 голосов на оффер.
- **4 ask-editor QAPage** — нужен редактор на постоянной основе. Отложено.
- **11, 25 квиз-подборщик** — уже есть в hero (`home-picker`).
- **12, 13, 14 email, боты, web push** — нужен трафик и юридический контур 152-ФЗ / 38-ФЗ ст. 18 (согласие на рекламу,
  локализация БД). Сначала идеи 1 и 6.
- **17 гео-подсказка** — ипотечных и бизнес-страниц почти нет.
- **23 ипотечный стек, 24 КБМ ОСАГО** — у rencredit нет ипотечных офферов. КБМ стоит рассмотреть во второй волне, вместе с
  портом статьи `kbm-osago` из finhelp: OSAGO-офферы есть (`cherehapa-osago`, `sk-soglasie-osago`, `vsk-osago`).
- **27 embed-виджеты** — после идей 4–8 они становятся дешёвыми, но ссылочный эффект спорный.
- **30, 52 карточки банков ЦБ** — у rencredit нет хабов банков.
