### 1.3 Найденные баги (не были описаны)
1. **Приветствие тратится впустую на скрытом маскоте.** `initMascotOnce` не смотрит на `data-no-mascot`. Если первый визит пришёлся на `/osago/` или `/vklady/`, через 1,8 с выполняется `open()`, оно пишет `fk:mascot:v1=1` и переводит маскота в `talk` под `display:none`. Потом человек переходит на `/zaimy/` и видит уже только мини-иконку: приветствие сгорело. Установлено чтением кода (`mascot.ts:53-58,81-93`). Проверить в браузере не удалось: Playwright-сессию параллельно занимал другой агент. Пока `noMascot` существует, лечится одной проверкой. В MVP баг исчезает сам, потому что маскот виден везде, кроме РКО (см. ниже).
2. **Плавающая группа не поднимается над `CtaSticky` в статьях и подборках.** `CtaSticky` рендерят `ArticleView.astro:11` и `[guide].astro:47`, но `stickyCta` в `BaseLayout` передаёт только `[dir]/[slug].astro:58`. Правило подъёма `body[data-sticky-cta] .float-group` (`decor.css:60`) в статьях не срабатывает. Полоса оставляет справа 68px (`cta.css:128`), а тело маскота 96×90 и выходит за группу шириной 48px. После прокрутки на 0,9 экрана маскот сдвигается на −58px (`decor.css:65`) и на 375px налезает на правую часть полосы, то есть на кнопку «Подобрать» и крестик. Вывод сделан по CSS-геометрии. **Перед правкой проверить скриншотом на 375×812.** Исправление — добавить `stickyCta` в 2 вызова `BaseLayout`. Это и есть нужное «avoid для CtaSticky», отдельный `IntersectionObserver` не требуется.
3. Мелочь. `mascot.ts:get` при исключении localStorage возвращает `null`, и маскот показывается. А skill `motion-system` требует в этом случае не показывать. В приватном режиме Safari приветствие будет на каждой полной загрузке. Исправлять вне этой задачи, только отметить.

## 2. Куда встраивается

### Совместимость
- Astro 7 static: шапка не persist и рендерится на сервере для каждой страницы, поэтому текст и ссылка CTA вычисляются при сборке, без JS.
- Маскот (`transition:persist="float"`) живёт между переходами, и пропсы ему не передать: DOM берётся со *первой* страницы. Тему для маскота поэтому кладём в саму страницу (атрибут на `<body>` и `<template>`), а `chrome.ts` читает её на каждом `astro:page-load`.
- `initMascot` берёт `opts.lines[i]` в момент вызова `say()` (`mascot.ts:45,55`). Значит, менять реплики можно, не трогая пакет `@pbn/motion`: держим ссылку на объект `opts` и подменяем `opts.lines`. Контракт `Character` (6 поз) не меняется.
- Хостинг: изменений нет, PHP не нужен.

### Вес
- JS: около +0,3–0,5 КБ gzip к `BaseLayout…js` (5,0 КБ): словарь тем уходит в HTML, а не в JS.
- HTML: около +1,5 КБ на страницу (одна поза `Character` в `<template>` и JSON реплик), после gzip меньше 0,5 КБ. CLS нет: шапка рендерится на сервере, маскот fixed.

### Набросок `chrome.ts` (главное)
```ts
let mascotOpts: MascotOptions | undefined;
let target = '#calc';
export function initMascotOnce() {
  initToTop();
  const el = document.querySelector<HTMLElement>('[data-mascot]');
  const tpl = document.querySelector<HTMLTemplateElement>('template[data-mascot-topic]');
  if (!el || !tpl) return;
  const t = JSON.parse(tpl.content.querySelector('script')!.textContent!) as { topic: string; lines: string[]; target: string; href: string };
  target = t.target;
  if (el.dataset.topic !== t.topic) {           // смена раздела: поза + реплики, без нового автопоказа
    el.dataset.topic = t.topic;
    el.querySelector('.mascot-body svg')?.replaceWith(tpl.content.querySelector('svg')!.cloneNode(true));
    if (el.dataset.state === 'talk') el.querySelector<HTMLElement>('[data-act="close"]')?.click();
  }
  if (mascotOpts) { mascotOpts.lines = t.lines; return; }
  if (document.body.hasAttribute('data-no-mascot')) return; // не тратить приветствие на скрытом
  mascotOpts = {
    storageKey: 'fk:mascot:v1',
    avoid: () => document.querySelector(target),
    lines: t.lines,
    onPick: () => {
      const node = document.querySelector(target);
      if (node) node.scrollIntoView({ behavior: prefersReduced() ? 'auto' : 'smooth', block: 'start' });
      else navigate(t.href);
    },
  };
  initMascot(el, mascotOpts);
}
```
Здесь нужна правка `onPick`: он должен читать актуальные `href` и `target` из модульных переменных, а не из замыкания `t`. Класс у svg должен остаться `mascot-char`. `avoid` вычисляется один раз при первой инициализации. Для MVP этого хватает, потому что первый показ всё равно один на визит.

## 3. Ценность и риски

### 3.1 Аудитория и ПФ
- **Рефинансирование: 15 из 22 статей, самый массовый органический вход.** Сейчас из такой статьи шапка и маскот ведут на главную, к калькулятору займов МФО. Для человека, который хочет закрыть долги, это неверный и потенциально вредный шаг: новый микрозайм поверх кредита. После правки он попадает в `/kredity/`. Это прямо соответствует запросам «рефинансирование кредита», «перекредитование под меньший процент», «объединить кредиты в один» (по ним названы статьи в `content/articles`).
- Страхование, вклады, дебетовые: сейчас «Подобрать займ» на `/osago/` уводит с целевой страницы на главную займов. Это лишний pogo-переход и визит, который для Метрики выглядит как отказ от раздела. После правки кнопка ведёт к `#offers` на той же странице, и визит углубляется, а не обрывается.
- SEO. Прямого ранжирующего эффекта нет. Косвенный эффект — меньше нецелевых возвратов и коротких визитов. Брендовые запросы «мерка маскот» — спекуляция: у персонажа нет имени, проверять нечего. Ссылкоёмкость нулевая.
- Оценки величины эффекта нет. Целей в Метрике пока нет (`dive-cpa-click-goals.md`), поэтому эффект нужно мерить, а не предполагать (п. 4).

### 3.2 Монетизация
- Выше CTR шапки и маскота в вертикалях кредитов, карт и страхования, где сейчас CTA просто не про этот раздел. Абсолютные цифры будут скромными: шапка с CTA видна только на ширине от 640px (`global.css:158-159`), на мобильном CTA есть только в бургер-меню.
- Риск каннибализации: на мобильном статьи уже есть `CtaSticky` с правильной темой. Маскот дублирует его, а не добавляет новый путь. Поэтому в статьях маскот должен остаться мини-иконкой без автопоказа после первого визита (так и сейчас).

### 3.3 Юридические риски
- **38-ФЗ «О рекламе».** «Покажу, кто одобрит» читается как обещание одобрения. Skill `ymyl-content` прямо запрещает такие обещания, и на сайте рядом написано «не гарантирует одобрение». Это противоречие и риск недостоверной рекламы, если реплику признают рекламой финуслуг. Нужно заменить. Реплика «Могу найти займ без процентов» называет одно условие, влияющее на стоимость займа (ставку). По ст. 28 ч. 3 реклама с одним таким условием обязана перечислить все условия, влияющие на полную стоимость. В бабле маскота это невозможно, поэтому реплику тоже убрать. Замена — нейтральная «Сравните ставку в день и ПСК до заявки». Ни одна реплика не называет конкретного кредитора, то есть по смыслу это навигация сравнительного сервиса, а не реклама объекта. Маркировка ЕРИР не нужна. Окончательная квалификация — за юристом владельца.
- **Финсоветы.** «Рефинансирование выгодно, если новая ПСК ниже текущей» — общее правило из финграмотности, не индивидуальная рекомендация. Деятельности инвестсоветника по 39-ФЗ здесь нет. Не писать «вам выгодно» и «вам одобрят».
- **152-ФЗ.** Флаг `fk:mascot:v1` и тема раздела не являются персональными данными, хранятся только в браузере и никуда не уходят. Согласие не нужно. Цели Метрики работают только после согласия (CookieBar), как и сейчас.
- **Товарный знак.** Имя персонажу не даём, проверка в ФИПС не нужна. Если имя появится, его вместе с «Мерка» проверить в ФИПС до рекламы (уже записано в BRAND.md).

### 3.4 Навязчивость и a11y
- Автопоказ остаётся один на визит, как сейчас. При смене раздела меняются только поза и реплики; новый выезд будет только в полной версии и после A/B.
- 375px: обязательно вместе с `stickyCta`-фиксом (баг 2), иначе маскот закрывает крестик полосы.
- `role="status" aria-live="polite"` у бабла уже есть. Смена текста при открытом бабле будет зачитана, поэтому при смене темы бабл закрываем.
- reduced-motion уже учтён (`decor.css`, `mascot.ts:47`).
