# Deep-dive: квиз «Снимем мерку за 4 вопроса» → талон «Ваша мерка»

Дата: 2026-10-19 · id: `snimem-merku-quiz` · сайт: rencredit-online.ru («Мерка»)
Код: `/Users/deniskononov/rencredit-pilot-wt/web/apps/rencredit` (Astro 7 static, `ClientRouter`, `@pbn/motion`).
На чём основано: `brand-engagement.md` E3, finhelp `offer-quiz-segment-personalization` (из `finhelp_ideas.json`),
`dive-moya-merka-personal-layer.md`, `dive-cpa-click-goals.md`, `dive-refi-calc.md`, `dive-refi-hub.md`.
Всё ниже перепроверено по коду worktree, контенту офферов и пулу, а также curl живого сайта и конкурентов на 19.10.2026.

## Вердикт

**`do_next`, 6/10. MVP 2 дня, полная версия ещё 3 дня.** Порядок: сначала `cpa-click-goals` (do_now), затем `refi-hub` и `refi-calc`, и только потом квиз.

- **Ветку займов квиз почти не улучшает.** Главная уже делает «сумма + срок + КИ → топ-3» (`HomeHero` + `home-picker.ts`).
  У 22 МФО всего 3 разные дневные ставки, у всех `approvalPct = 0`. На вопрос «почему эти три» по МФО данные отвечают
  только так: «выдаёт такую сумму на такой срок», «0% на первый займ» и «по данным МФО рассматривает заявки с просрочками».
  Квиз этот ответ лишь пересказывает.
- **Новое в квизе одно: вопрос «цель».** Он переводит человека из МФО (2 250–4 350 ₽ за нового клиента) в вертикали,
  которые платят больше или сопоставимо и где у нас есть офферы: кредитные карты (Т-Банк 4 320 ₽, Уралсиб 3 525 ₽, Т-Драйв 3 690 ₽),
  рефинансирование (Т-Банк 5 000 ₽, Альфа 1 750 ₽), кредит наличными (Т-Банк 3 332 ₽), страхование (Полис812 и Черехапа: 13,5–50% от премии).
  Это реальные деньги, но на сайте с ИКС 0 они придут не скоро, и измерить их пока нечем: на сайте 0 `reachGoal`.
- **Ветке «закрыть долги» сейчас некуда вести.** `/refinansirovanie/` отдаёт 404, калькулятора рефинансирования и
  ПДН-самопроверки в коде нет, есть только 23 статьи категории `refinansirovanie`. Значит, сначала нужен хаб и калькулятор из соседних dive.
- **«Без JS работает как `<form method=get>`» — так не получится.** Хостинг статический, и `/podbor/?goal=…` без JS
  не отрендерит результат, витрина тоже читает `?sum` только клиентом (`offers-ui.ts:62`). Честный фолбэк такой:
  первый шаг «цель» сделать обычными ссылками на хабы, а JS их перехватывает и продолжает квиз.
- **Пример «sravni.ru/kredity/scoring/» неудачный.** Это кредитный рейтинг через три БКИ с регистрацией
  (title «Кредитный рейтинг: проверить онлайн бесплатно сразу в трех БКИ»), то есть сбор ПДн, а не квиз.
  У конкурентов страницы-квизы как формат не прижились: `sravni.ru/zaimy/podbor/` отдаёт 410, `banki.ru/microloans/podbor/` 404, `vbr.ru/zaimy/podbor/` 404.
  Это минус к SEO-ценности `/podbor/` как отдельной посадочной.
- **В идее нет одного вопроса, который нужен.** С 01.10.2026 действует ограничение: МФО не может выдать третий заём с ПСК выше 200%,
  если у человека уже два таких непогашенных (закон принят в декабре 2025, следующий этап с 01.04.2027; **номер закона и даты сверить
  по consultant.ru перед публикацией**). У нас `pskMax ≤ 200` только у **2 из 22** МФО (ФинТерра и Деньги Сразу, 197,1%).
  Вопрос «Сколько займов сейчас открыто: 0 / 1 / 2 и больше» честно отводит человека от отказов: при ответе «2+» обычные МФО
  не показываем и ведём в рефинансирование или в ПДН. Это YMYL-сигнал и отличие от витрин, которые показывают всем одно и то же.

квиз даст сопоставимые 2–3 КБ, бюджет motion-скилла 30 КБ.

## 2. Ценность

### 2.1 Поиск и трафик

- Запросы-кандидаты для `/podbor/`: «подобрать займ онлайн», «подбор кредита онлайн», «какой займ выбрать», «где взять деньги до зарплаты»,
  «подобрать кредитную карту». **Частоты по Wordstat не проверялись.** Head-выдачу по ним держат витрины (sravni, banki), а не квизы.
  Отдельная посадочная `/podbor/` трафика почти не даст, рассчитывать на неё нельзя.
- Основная ценность — **ПФ на внутреннем трафике**: человек со статьи или из hero за 30–60 секунд получает ответ, не возвращаясь в выдачу.
  Это касается и вертикалей, где у нас нет калькулятора (карты, страхование).
- Ссылкоёмкость низкая: подборщики не цитируют. Брендовая метафора «снять мерку» хороша для соцсетей и маскота, не для ссылок.

### 2.2 Монетизация

- Квалифицированный клик: цель известна, и человек попадает в нужную вертикаль, а не в МФО по умолчанию.
- Сегмент `goal` меняет порядок `Showcase`/`CtaTop3` на следующих страницах. **Это полная версия**: без целей Метрики
  эффект не измерить, а без `fk:merka` писать некуда.
- Честный потолок. Пока на сайте мало повторных визитов (ИКС 0, новый движок с 17.10), выигрыш даст в основном шаг «цель → вертикаль».
  Пересортировка по сегменту окупается на возвратах, а их ещё нет.

### 2.3 Юридические риски

| Норма | Риск в квизе | Что делать |
|---|---|---|
| 38-ФЗ ст. 5 ч. 3 (недостоверность), ymyl-скилл | «подойдёт вам», «одобрят», «шанс 87%» | Только «подходят по сумме и сроку по данным организаций». Строка `cta-fine` из `CtaTop3`. Процентов шанса нет, их и нечем считать |
| 38-ФЗ ст. 28 ч. 3 | В объяснении «почему» назвать ставку без ПСК | «Почему» собирается из фактов оффера. Ставку упоминать только при `showsRate(o)`, иначе `NO_RATE`. Карточки уже соблюдают правило |
| Маркировка (erid) | Талон без пометки «Реклама» | `OfferCard ad` + `AdMark` уже есть, свои карточки не верстать |
| Ограничение «третьего дорогого займа» с 01.10.2026 | Показ МФО с ПСК 292% человеку с двумя открытыми займами = почти гарантированный отказ | Вопрос «сколько займов открыто». При «2+» — рефинансирование и ПДН, МФО не показывать. **Номер закона сверить** |
| 152-ФЗ | КИ и долги — сведения о финансовом положении. Связка с ClientID Метрики может сделать их ПДн | Ответы хранить только в `localStorage`. В Метрику отправлять `quiz_start`/`quiz_finish` с параметром `goal`, **без КИ, суммы и числа займов**. Метрика по-прежнему грузится только после согласия |
| Финсоветы | Императив «возьмите», «оформите ещё» | Тон «вот что подходит под условия». Ветка долгов без новых займов (как в `dive-moya-merka`, ≥3 «брал») |
| `priority` = коммерческое поле | Порядок «лучших» на деле партнёрский | Под талоном: «Порядок с учётом условий партнёров» + ссылка на «Как мы зарабатываем» |

## 3. MVP (2 дня)

### 3.1 Объём

1. `src/data/quiz/tree.json` (около 80 строк): узлы `goal → (sum, term | sub | protect | open_loans) → ki`, у каждой цели `kind`/`category`,
   диапазоны слайдеров, фолбэк-хаб. Правила — данные, не код.
2. `src/pages/podbor.astro`: H1 «Снимем мерку: подбор займа, кредита, карты или страховки», 3 абзаца о том, как работает подбор,
   5 вопросов FAQ (тексты по `ymyl-content`), `canonical` на `/podbor/` (параметры в индекс не пускать).
   На сборке в страницу рендерятся **все** кандидаты (как `ordered` в `HomeHero`): 22 МФО (`PickTicket`), 11 кредитов и карт,
   топ-страховки. Все скрыты атрибутом `hidden`, скрипт только показывает и переставляет. Скрипт карточки не создаёт, значит XSS-поверхности нет.
3. `src/components/quiz/Quiz.astro` + `src/scripts/quiz.ts` (около 120 строк):
   - шаг 1: 5 целей. Каждая цель — `<a href="/zaimy/">`, `/kredity/`, `/refinansirovanie/` (после хаба), `/karty/`, `/strahovanie/`.
     Без JS это обычная навигация, с JS — `preventDefault` и следующий шаг;
   - шаги рисуются переключением `hidden` у `<fieldset>`, фокус переходит на `<legend>` (a11y), «Назад» — `history.replaceState`;
   - результат: `pick()` из `home-logic.ts` по нужному `kind`, `nearest()`, если пусто, затем фолбэк-хаб;
   - строка «почему» на каждой карточке собирается из 3 фактов: сумма/срок, `zero_percent` + `freeDays`, `bad_history`. Для карт — льготный период из `termMaxDays`;
   - URL `?goal&sum&term&ki&open` через `replaceState`: результатом можно поделиться, и `home-picker` читает тот же формат;
   - запись `fk:merka = {goal, sum, term, ki, t}` в try/catch. При повторном заходе — «Продолжим: 15 000 ₽ на 14 дней?»;
   - `data-goal="quiz_start|quiz_finish"` на кнопках, общий хендлер из `dive-cpa-click-goals.md` (если его ещё нет, цели не шлём).
4. Маскот: на итоговом шаге `think` → `cheer`, кроссфейд 250 мс. При `prefersReduced()` смена мгновенная.
   В `chrome.ts` `onPick` без `#calc` ведёт на `/podbor/`, а не на `/#calc`. Это одна строка.
5. Кросс-ссылки: `CtaCallout` в статьях карт и страхования ведёт на `/podbor/?goal=card|protect`, это одна строка в `lib/cta.ts`.

### 3.2 Не входит в MVP

- Модалка из шапки и маскота. Вторая точка UI с focus-trap, а страница решает ту же задачу. Добавить, если `quiz_finish/quiz_start` > 40%.
- Пересортировка Showcase/CtaTop3 по сегменту — полная версия.
- Ветка ПДН-самопроверки. Пока E6 нет, ветка «долги» ведёт на хаб и калькулятор рефинансирования или на статью.

### 3.3 Фолбэки (обязательные)

- «Покупка» + КИ «с просрочками»: офферов нет. Текст: «У кредитов в нашей витрине нет пометки о рассмотрении заявок с просрочками»,
  затем статьи о КИ, а также МФО с `bad_history`, только если сумма ≤ 100 тыс., с явной припиской про ПСК.
- «Займ» + «2 и больше открытых займов»: МФО не показываем, вместо них рефинансирование, «как не уйти в спираль» (статьи) и ссылка на МФЦ/банкротство (статья).
- Кредитные карты с `poolId` вне пула: не показывать, пока `sync-pool` не подтвердит статус `approve`.
- Пустой результат в любой ветке: хаб вертикали, а не пустой экран.

### 3.4 Как проверить

- `node scripts/check-content.mjs`, `astro check`, сборка: `podbor/index.html` с кандидатами, без JS шаг 1 состоит из рабочих ссылок.
- Маленький `quiz.test.ts` (или `assert` в `__main__`) на дерево: из каждой ветки достижим результат или фолбэк, ни одна ветка
  «займ» с `open=2+` не возвращает МФО с `pskMax > 200`.
- Playwright 375/768/1440: шаги переключаются с клавиатуры, при reduced-motion движения нет, CLS = 0 (карточки уже в DOM).

## 4. Полная версия (ещё около 3 дней)

1. **Сегмент в витрине.** `offers-ui.ts`: в сортировке `rec` добавить бонус к `prio` по `fk:merka.goal`/`ki`
   (например, `bad` поднимает `bad_history`, `goal=card` в статье поднимает кредитные карты в `CtaTop3`). Порядок менять **до** показа
   (карточки ниже первого экрана, Flip уже есть). Серверный HTML для всех одинаковый, так что клоакинга нет.

3. Ветка ПДН (E6) и встроенный мини-калькулятор рефинансирования, когда они появятся.
