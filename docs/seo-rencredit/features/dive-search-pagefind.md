# Deep-dive: рабочий поиск на rencredit (search.json → Pagefind)

Дата: 2026-10-19. Идея `search-pagefind`. Код, данные и конфиги не менял. Сборку и npm install не запускал. Проверял по уже собранному `web/apps/rencredit/dist` (сборка от 17.10) и живому `https://rencredit-online.ru/search.json`.
Основа: `finhelp-adapt-2.md` п. 8, `current-state.md` §2.3, `oss-repos-astro7.md`, `docs/seo/features/search-ux.md` (finhelp). Их выводы здесь перепроверены и поправлены под rencredit.

## 0. Вердикт

**do_now, но в другом порядке, чем в идее.** Шаг 1 (полный `search.json`, синонимы, клавиатура, цели) займёт полдня. Он чинит то, что сейчас видно сразу: на «кредитка» и «займ на карту» поиск отвечает «Ничего не найдено». Pagefind (шаг 2) — ещё около дня. Его стоит делать вместе с шагом 1 или сразу после переноса статей прошлых агентов, когда текста станет больше.

Эффект я понизил бы с high до **medium**. Внутренним поиском пользуется небольшая доля сессий, а индексируемых страниц всего 83. Прямого SEO-эффекта у поиска нет. Польза в поведенческих факторах, в том, что поиск перестаёт выглядеть сломанным, и в списке пустых запросов для контент-плана.

Пять пунктов идеи оказались неверными (подробно в §2):
1. В сборке не 228 страниц, а 83 индексируемых: 144 HTML — редиректы `/go/`, ещё один — 404.
2. Legacy `/credit/*.html` в индекс **уже попадают** через `articleHref()`. Не хватает только новостей, главной и хабов.
3. У 50 сервисов (страхование, вклады, дебетовые, РКО) **нет своих страниц**. Индексировать их можно только как «название → посадочная категории», без `/go/`.
4. **Синонимов в Pagefind нет.** «Кредитка» не встречается ни в одной из 83 страниц, так что Pagefind сам по себе её тоже не найдёт. Словарь синонимов нужен на клиенте в обоих шагах.
5. Шаг в `deploy-beget.sh` не нужен. Pagefind лучше запускать через Node API в `astro:build:done` после `legacyHtmlFiles`. Тогда `npm run build`, CI и deploy-скрипт остаются без изменений.

Сейчас весь JS сайта в `_astro/` — 53 КБ gzip.

## 3. Ценность

- **Пользователь.** Находит ответ внутри статей («что будет при просрочке 3 дня», «как снять самозапрет»), а продукты — по разговорным названиям («кредитка», «микрозайм», «автогражданка»).
- **Поведенческие факторы.** Пустая выдача сейчас ведёт к возврату в Яндекс. Рабочий поиск дольше держит сессию. На 83 страницах эффект умеренный, но растёт вместе с контентом, например после переноса статей прошлых агентов.
- **SEO.** Прямого эффекта нет. Sitelinks searchbox Google убрал в ноябре 2024, Яндекс `SearchAction` не использует, поэтому JSON-LD `SearchAction` не добавлять. Страницу `/poisk/` для SEO не делать, а если она появится — `noindex`.
- **Контент-план.** Цель `search_empty` с текстом запроса — это бесплатный список тем, которых нет на сайте.
- **Монетизация.** Косвенная: выдача ведёт на обзоры и подборки, на которых стоят CTA `/go/`. Прямых ссылок `/go/` в выдаче нет.
- **Ссылки.** Ссылок на сайт поиск не принесёт.

**Юридические риски**
- **152-ФЗ.** В текст запроса человек может вписать ФИО, телефон или номер паспорта. Цели уходят только при согласии: `ym` до согласия не существует, и вызов становится no-op. Запрос перед отправкой обрезать до 60 символов, а последовательности из 4 и больше цифр заменять на `#`. В `localStorage` запросы не хранить.
- **38-ФЗ ч. 3 ст. 28.** Сниппет Pagefind из обзора может вытащить «0,8% в день» без ПСК. Для результатов типа «Обзор» показывать вместо сниппета `meta description` либо пометить блок условий `data-pagefind-ignore`. Ставки в выдаче не показывать вообще.
- **Финсоветы.** Не затрагиваются: поиск ничего не рекомендует.

## 4. MVP (≈ полдня): шаг 1 без новых зависимостей

1. **`src/pages/search.json.ts`**
   - добавить `getNews()` (`k: 'Новость'`) и главную;
   - добавить `getServices()`: `{t: s.name, u: SERVICE_META[s.category].href + '#offers', k: SERVICE_META[s.category].label}`. Без `/go/`, без ставок;
   - новое поле `d`: `description` или `summary` для статей и обзоров, до 140 символов. Индекс вырастет примерно до 25–30 КБ (оценка), gzip уже включён (`.htaccess:297`);
   - поле `kw` собирать из словаря синонимов.
2. **`src/lib/search-synonyms.ts`** (новый файл, около 30 строк). Группы, где первое слово канон: `кредитная карта ← кредитка, кредитную, кк`; `займ ← заём, микрозайм, микрокредит, мфо, займы`; `рефинансирование ← рефинанс, перекредитование`; `кредитная история ← ки, бки, кредитный рейтинг`; `осаго ← автогражданка`; `самозапрет ← запрет на кредиты`; `просрочка ← долг, неустойка, коллекторы`; `плохая кредитная история ← плохая ки, испорченная`. Один и тот же модуль используется при сборке (`kw`) и на клиенте (расширение запроса).
3. **`src/scripts/chrome.ts:56-95`**
   - токенизировать запрос, каждый токен длиннее 5 символов урезать до 5 (грубый стемминг: «просрочка» и «просрочке» дают «проср»), расширить синонимами;
   - запись проходит, если каждый токен совпадает с началом слова в `t`, `kw` или `d`;
   - вес: заголовок 3, `kw` 2, `d` 1; по типу Подборка/Раздел > Обзор > Статья > Новость;
   - стрелки ↑/↓ двигают `aria-selected`, Enter открывает активную ссылку через `navigate()`;
   - `role="listbox"` на `ul`, `aria-live="polite"` на счётчик;
   - пустой запрос — 4 быстрые ссылки (займы на карту, без процентов, кредитные карты, страхование).
4. **Цели.** В inline-скрипт `BaseLayout.astro` добавить одну строку `window.fkGoal = (n, p) => window.ym && window.ym(id, 'reachGoal', n, p)`. В `chrome.ts` вызывать `search_query` с debounce 1,5 с и `search_empty` с параметром `{q}` после очистки по правилам 152-ФЗ из §3. В интерфейсе Метрики завести две JS-цели.
5. **Проверка.** Небольшая `assert`-проверка матчинга: «кредитка» находит `/karty/`, «снять самозапрет» находит новость, «займ на карту» — `/zaimy-na-kartu/`. Ручной прогон в `astro preview`: Esc, стрелки, мягкий переход и повторное открытие.

После MVP находятся «кредитка», «микрозайм», «займ на карту», «осаго», страхование, вклады и новости. Не находится то, что есть только в теле статьи («снять самозапрет», «просрочка 3 дня»): для этого нужен шаг 2.

## 5. Полная версия (+1 день): Pagefind поверх того же диалога

1. **devDependency `pagefind@1.5.2`**, точная версия без `^`.
2. **`astro.config.mjs`.** Добавить интеграцию `pagefindIndex()` **после** `legacyHtmlFiles()` в `integrations`: хуки `astro:build:done` выполняются по порядку, поэтому `credit/<slug>.html` к этому моменту уже переименованы. Внутри — `createIndex()`, `addDirectory({ path: dist })`, `writeFiles({ outputPath: dist + '/pagefind' })`, лог количества страниц и ошибок. `deploy-beget.sh`, GitHub workflow и npm-скрипты менять не нужно.
3. **Разметка**
   - `BaseLayout.astro:147`: `<main id="main" data-pagefind-body={noindex ? undefined : ''}>`. Когда на сайте есть хотя бы одна страница с `data-pagefind-body`, страницы без этого атрибута (`/go/` со своим `<html>`, 404, noindex-посадочные) в индекс не попадают;
   - `data-pagefind-ignore` повесить на Showcase/Catalog/CompareTable, OfferCard, CTA-блоки, Breadcrumbs, FAQ-витрины офферов и блок условий обзора (38-ФЗ, §3);
   - `data-pagefind-meta="type:Статья"` (Обзор / Подборка / Новость / Раздел) в шаблонах;
   - `data-pagefind-weight="3"` для `<h1>`.
4. **`chrome.ts`**
   - при первом открытии: `const pf = await import(/* @vite-ignore */ PF_URL)` с `PF_URL = '/pagefind/pagefind.js'` в переменной, чтобы Vite не резолвил путь;
   - `pf.options({ excerptLength: 18 })`;
   - запрос с синонимами: `pf.debouncedSearch(expanded, {}, 250)`, затем `data()` для первых 8 результатов. Заголовок брать из `meta.title`, тип — из `meta.type`, сниппет (с `<mark>`) показывать только для Статья/Новость;
   - собственные записи `search.json` (сервисы, разделы) идут первыми: Pagefind про них не знает, у сервисов нет своих страниц;
   - при ошибке импорта (`astro dev`, 404, старый браузер без wasm) — фолбэк на шаг 1.
5. **`.htaccess`**: `<If "%{REQUEST_URI} =~ m#^/pagefind/.+\.pf_#">` → `immutable` на год; `pagefind.js` и `pagefind-entry.json` — `max-age=300, must-revalidate`. Без этого после деплоя клиент может долго держать старый entry.
6. **Деплой без `--delete`.** Старые чанки `.pf_*` копятся на сервере. Это безвредно, потому что `pagefind-entry.json` ссылается только на актуальные. Раз в квартал можно чистить вручную.
7. **Дальше, по данным целей:** исправление раскладки (`ghjcnj` → «просто», около 10 строк, частая ошибка рунета). Пустая модалка показывает «недавно смотрели» из localStorage (идея `recently-viewed`). Ответы «не нашли» передаются в бриф контент-плана раз в месяц.

## 7. Риски

- Новая devDependency с бинарником: npm-пакет тянет платформенный бинарь `@pagefind/*`. В CI на ubuntu и локально на macOS это работает, `npm ci` с lockfile подтянет нужный.
- Если забыть `data-pagefind-ignore` на витринах, выдача забьётся одинаковыми карточками офферов, а в сниппеты попадут ставки без ПСК.
- Синонимы требуют ручной поддержки. Расширять словарь по отчёту `search_empty`, а не заранее.
- В Метрику не отправлять полный текст запроса, даже после согласия (см. §3).
