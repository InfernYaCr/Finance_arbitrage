Код: `/Users/deniskononov/rencredit-pilot-wt/web/apps/rencredit` (Astro 7.3.8, статика, Beget/Apache, живой сайт уже на Astro).
Основа: `news-data-automation.md` §5.5 и `dive-news-inbox-pipeline.md`. Там идея только названа, здесь она проверена: `curl` по источникам, Яндекс-подсказки, прототип генератора `.ics` с самопроверкой (лежит в scratchpad, в репо ничего не менялось). Ставки и заседания ЦБ разобраны в `dive-key-rate-hub.md`, биометрия в `dive-C6-biometrics-ebs.md`, лимиты ПСК в `dive-psk-checker.md`. Здесь их не повторяю, использую только как источник дат.

## Вердикт

**do_next. Оценка 5/10, MVP займёт около 1,5 дня.** Делать в урезанном и перестроенном виде, не так, как сформулировано в идее.

1. **Ежемесячный выпуск про «1 ноября» делать не стоит.**
   - Изменений для заёмщика, которые вступают в силу 01.11.2026 и закреплены опубликованным актом, я не нашёл ни одного.
   - Единственный кандидат — идентификация в МФО только по лицу с 01.11. Он подтверждён одной публикацией в СМИ, нормативного акта нет (`dive-C6`). По правилу самой идеи («в календарь только акты с реквизитами») он не проходит.
   - Ноябрьский выпуск получился бы пустым или стал бы пересказом чужих общих дайджестов (мигранты, маркировка), а это не наша тематика.
2. **Широкий запрос нам не достанется.** Запрос «что изменится с 1 ноября 2026» в подсказках Яндекса есть. Но выдачу держат СМИ и правовые базы с общей тематикой: Консультант, Гарант, РГ, РБК, региональные издания. Финансовый CPA-сайт без статуса СМИ с ними не конкурирует.
   - Узкий спрос есть только вокруг крупных дат. Подсказки: «изменения в кредитовании с 1 апреля 2026», «…с 1 апреля», «…с 1 октября». Конкуренты по таким выпускам: vbr.ru, ppt.ru, bankiros.ru, incrussia.ru.
   - Значит, ритм нужен **по ключевым датам**, а не ежемесячный: 1 января, 1 марта, 1 апреля, 1 июля, 1 сентября, 1 октября. Получается примерно 4–6 выпусков в год.
3. **Первым выпуском сделать «Что изменится для заёмщиков с 1 января 2027».** Публиковать 20–25 декабря. Это самый сильный сезонный запрос года: в подсказках есть «что изменится с 1 января 2027 года (в россии)». Следом идут 1 марта 2027 (МКК и ЕБС) и 1 апреля 2027 (второй этап закона о микрозаймах).
4. **Страницу-календарь `/kalendar-izmenenij/` и `.ics` стоит сделать сразу.**
   - Это дёшево: 0 КБ JS, одна страница и один эндпоинт.
   - Даты уже проверены: 8 заседаний ЦБ на 2027 год и 2 оставшихся в 2026-м, 01.12.2026 (налоги), 01.03.2027, 01.04.2027.
   - Календарь нужен как постоянный хаб, на который ссылаются новости, хаб ключевой ставки и статьи про МФО.
   - Трафика он сам по себе даст мало. Его ценность в перелинковке и в возвратах: у каждого события в календаре пользователя есть URL на сайт.
5. **Модель данных нужна другая.** Предложенное поле `news.effectiveDate` даёт одну дату на новость. В дайджесте же 3–8 пунктов с разными датами. Правильно сделать отдельную коллекцию `changes` в одном JSON-файле со ссылкой на новость `news: reference('news')`. Из неё собираются календарь, `.ics` и список пунктов внутри выпуска. Источник правды один, дубля дат нет.
6. **Автогенерация черновика агентом не работает.** Нормальных структурированных дат вступления в силу нет ни в одном источнике (§1). Выпуск — это 1–2 часа ручной работы редактора, затем fact-checker.

### 2.2 Модель данных (MVP)

`src/content.config.ts`, новая коллекция (около 15 строк):

```ts
const changes = defineCollection({
  loader: file('src/content/changes.json'),
  schema: z.object({
    date: z.coerce.date(),                        // дата вступления в силу / событие (весь день, МСК)
    title: z.string().max(90),                    // попадает в SUMMARY календаря
    summary: z.string().max(300),                 // «что это значит для заёмщика», без советов
    kind: z.enum(['law', 'cbr', 'tax', 'meeting']),
    act: z.string().optional(),                   // «Федеральный закон от 29.12.2025 № …-ФЗ»
    source: z.url(),                              // первоисточник: pravo.gov.ru, cbr.ru, nalog.gov.ru
    href: z.string().startsWith('/'),             // раздел сайта: /zaimy/, /vklady/, /kredity/ …
    news: reference('news').optional(),           // выпуск или новость, где пункт разобран
    checkedAt: z.coerce.date(),                   // когда fact-checker сверил дату
  }),
});
```

Правила в `check-content.mjs` (около 20 строк):
- `kind: 'law'` без `act` → ошибка.
- `source` с хостом не из списка `pravo.gov.ru | cbr.ru | nalog.gov.ru | minfin.gov.ru | government.ru | consultant.ru` → ошибка. Агрегаторы и СМИ не проходят.
- `checkedAt` старше 90 дней при будущей `date` → предупреждение.
- Прошедшие даты остаются в архиве страницы, ошибкой не считаются.

### 2.4 Генератор `.ics`: прототип и найденные грабли

Прототип: `scratchpad/icsproto/ics.mjs`, Node 24, без зависимостей. На событии 01.04.2027 он выдаёт 848 байт, самая длинная строка — 75 октетов, все проверки проходят.

Что обязательно по RFC 5545 и где легко ошибиться:
1. **Фолдинг по 75 октетам, а не символам.** Кириллица в UTF-8 занимает 2 байта, поэтому строка переносится примерно через каждые 37 букв. Резать надо по символам (`for…of`), иначе разорвётся многобайтовый символ.
2. **CRLF везде**, включая конец файла.
3. **Экранирование TEXT:** `\` → `\\`, `;` → `\;`, `,` → `\,`, перевод строки → `\n`.
   - В прототипе я сам первым делом получил неэкранированную `;`. Её поймала только явная проверка, `console.assert` молчит. Поэтому самопроверка должна бросать исключение, и место ей в `check-content.mjs`.
4. **События на весь день:** `DTSTART;VALUE=DATE:20270401` + `DTEND;VALUE=DATE:20270402`. Конец исключающий, без времени и TZ, тогда событие не сдвигается по часовым поясам. Заседания ЦБ можно дать со временем 13:30 `TZID=Europe/Moscow`, но тогда понадобится `VTIMEZONE`. Для MVP тоже делаем их событиями на весь день.
5. **Обязательные поля:** `UID` (стабильный, `id@rencredit-online.ru`, иначе при повторном импорте будут дубли), `DTSTAMP`, `PRODID`, `VERSION:2.0`.
6. **Обновления у подписчиков:** `REFRESH-INTERVAL;VALUE=DURATION:P1D` и `X-PUBLISHED-TTL:P1D`. Google обновляет подписки сам, примерно раз в 12–24 часа. У тех, кто скачал файл разово, исправления не появятся. Поэтому на странице главная кнопка — «Подписаться», а не «Скачать».
7. **`TRANSP:TRANSPARENT`**, чтобы событие не помечало день у пользователя как «занят».

### 3.1 Запросы (Яндекс-подсказки, `suggest.yandex.ru`, lr=213, 19.10.2026; частот Wordstat нет, доступа к нему у меня нет)

| Кредитные по крупным датам | «изменения в кредитовании с 1 апреля 2026», «… с 1 апреля», «… с 1 октября» | **Средний.** Конкурируем с vbr, ppt, bankiros, но тема наша, и у нас есть свои разделы для ссылок |

**Оценка трафика.** Это гипотеза, не замер. Выпуск к 1 января может дать порядка десятков–сотен визитов в неделю пика, если выйдет в топ-10 по кредитному хвосту. Выпуск к рядовому месяцу — около нуля. Сама страница календаря — единицы визитов в день. Яндекс Новости отпадают: у «Мерки» нет статуса СМИ (`dive-news-inbox-pipeline`).

### 3.2 Поведенческие факторы и возвраты

- **Плюсы.**
  - У страницы понятная структура «ближайшее → по месяцам», клик из каждого пункта ведёт в раздел. Это хорошая глубина просмотра для тех, кто пришёл из выпуска.
  - Подписка в календаре — единственный на сайте канал возврата без email и push, и он не требует персональных данных: событие с URL сайта всплывает у пользователя за день до даты.
- **Минусы.** Подписываться будут единицы процентов от и так небольшой аудитории. Как источник повторных визитов это мало, как сигнал полезности — нормально.

### 3.3 Ссылкоёмкость и монетизация

- **Ссылки.** Чуть выше средней по сайту. Таблицу «даты по закону о микрозаймах + ЕБС + ПСК» с первоисточниками могут цитировать форумы и Q&A. Новостные заметки сайта ссылок почти не собирают. Активный аутрич не планирую.
- **Монетизация.** Прямая — около нуля. В каждом пункте нейтральная ссылка на раздел: `/zaimy/`, `/kredity/`, `/vklady/` (налог на проценты, заседание ЦБ → ставки по вкладам), рефинансирование.
  - На странице календаря допустим один `CtaNext` внизу: это не новость.
  - Внутри выпуска-новости — только одна нейтральная ссылка, по правилу `news-pipeline`.
  - Основная польза для денег — косвенная: свежесть и перелинковка на коммерческие разделы.

### 3.4 Юр. и YMYL-риски

| Риск | Мера |
|---|---|
| **Неверная дата у пользователя в календаре** (YMYL, самый серьёзный) | Только акты с реквизитами или официальные календари ЦБ и ФНС. Обязательное поле `checkedAt`, fact-checker сверяет до merge. Подписка (а не разовая загрузка) — чтобы исправления доезжали до пользователей. Если дату перенесли, событие **меняется**, `UID` остаётся тот же |
| Законопроект подан как закон | В схеме нет статуса «законопроект». `kind: 'law'` без `act` роняет проверку |
| **38-ФЗ, ст. 5 и ст. 28** | Никаких «успейте взять займ до 1 апреля», таймеров и призывов торопиться. В карточке события нет офферов, `erid` и логотипов МФО. Тогда страница остаётся информационной и не считается рекламой. Если когда-нибудь появится оффер — маркировка и правило `offer-placement` |
| Индивидуальная финансовая рекомендация | Блок «что это значит» описывает только правило: «МФО не выдаст третий займ с ПСК > 200%». Не «вам стоит / не стоит». Про ключевую ставку прогнозов не даём. Подсказка «заседание цб … прогноз» — не наша |
| 152-ФЗ | Персональные данные не собираются: `.ics` статичный, подписка анонимная, в ссылках Google только текст события. Политику конфиденциальности менять не нужно |
| Авторское право | Аннотации Консультанта не берём, только реквизиты и свои формулировки. Цитата — одна и короче 15 слов (`news-pipeline`) |
| `Event` в JSON-LD | **Не размечать.** Вступление закона в силу — не мероприятие, Google считает такую разметку нарушением правил для Event. Для страницы — `CollectionPage` или без JSON-LD, для выпуска — `newsArticle()` из `@pbn/core` |
| Календарь устарел | Расписание редакции: 20–25 декабря, февраля, марта, июня, августа, сентября. В каждый день заседания ЦБ — проверка и добавление новых дат |

## 4. MVP и полная версия

### MVP (1,5 дня, до 20 декабря)

1. **Коллекция `changes` + `changes.json`** с 10–14 проверенными датами из §1 и правила в `check-content.mjs`. **0,25 дня.**
2. **`src/lib/ics.ts` + `kalendar-izmenenij.ics.ts`** + самопроверка в `check-content.mjs` + 3 строки в `.htaccess`. **0,25 дня.**
3. **`/kalendar-izmenenij/`:**
   - «Ближайшие 3», список по месяцам, архив;
   - блок подписки (§2.5);
   - ссылки из футера, `search.json`, хаба ключевой ставки и новости от 01.10.2026;
   - `RESERVED_SLUGS`.

   **0,5 дня.**
4. **Выпуск «Что изменится для заёмщиков с 1 января 2027»** (`draft: true` → fact-checker → публикация 20–25.12). **0,5 дня работы редактора.** В выпуске:
   - предельные ПСК на I кв.;
   - макролимиты ЦБ на I кв. (если решение уже вышло);
   - напоминание про 01.03 и 01.04.2027;
   - 18.12 — заседание ЦБ.
5. **Ноябрьский выпуск не делать.** 01.12 (налог) и 18.12 (ЦБ) просто вносим в календарь.

**Критерии готовности:**
- `dist/kalendar-izmenenij.ics` открывается в Apple Calendar и Google по подписке без ошибок;
- `curl -I` отдаёт `content-type: text/calendar`;
- проверка контента падает на записи без `source` или `act`;
- на странице 0 КБ клиентского JS.

### Полная версия (+2–3 дня, после 2–3 выпусков и только если выпуск к 1 января наберёт показы)

- Выпуски по ключевым датам: 1 марта, 1 апреля, 1 июля, 1 сентября, 1 октября 2027. Каждый — новость, а её пункты лежат в `changes` со ссылкой `news`.
- Блок «Ближайшее изменение» (1 строка) в статьях про МФО и ПСК, через тот же `getCollection('changes')`.
- Заседания ЦБ со временем 13:30 МСК (`VTIMEZONE`). Даты брать из `facts.json` → `meetings[]`, если `dive-facts-json-build-time` будет сделан, чтобы не вести даты в двух местах.
- Фильтр по типу на странице (займы / кредиты / вклады / налоги) на CSS `:has()` с радиокнопками, без JS. Плюс отдельные `.ics` по типу, если подписок станет заметно много.
- Полуавтомат: `news_inbox.py` (`dive-news-inbox-pipeline`) помечает в inbox пункты Консультанта и ЦБ с фразами «вступает в силу / с 1 …». Это детектор, дату всё равно сверяет человек.

**Что не делать:**
- автопубликацию;
- разметку `Event`;
- ежемесячные выпуски «для галочки»;
- генерацию дайджеста LLM по чужим обзорам.
