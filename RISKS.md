# Pre-mortem: почему проект может провалиться

Этот документ описывает наиболее вероятные причины провала PBN-фабрики
в первые 6 месяцев и конкретные меры по их устранению.

Читать перед началом работы над любым треком B. При старте новой сессии —
проверять, не создаёт ли планируемая задача новый риск из списка ниже.

Вероятность: 🔴 высокая · 🟡 средняя · 🟢 низкая (при правильной реализации)

---

## Группа A — SEO-риски (нет трафика → нет дохода)

### A1 🔴 Нет внешних backlinks

**Симптом:** сайты проиндексированы, но стоят на позициях 50-100+, трафик нулевой.

**Причина:** статические сайты без единой входящей ссылки не ранжируются
в конкурентных нишах ни в Яндексе, ни в Google. Алгоритмы 2025-2026 учитывают
ссылочный авторитет как ключевой фактор для коммерческих запросов.

**Митигация:**
- B7.1: базовая ссылочная стратегия — крауд (форумы, Q&A, комментарии блогов)
  минимум 5-10 ссылок на сайт до индексации
- Выбор донора для B1.4 под нишу с информационными запросами (ниже конкуренция)
- Целевые запросы: информационные (как, что, почему) ранжируются легче
  коммерческих (купить, цена, заказать)

### A2 🔴 Footprint-детекция сети

**Симптом:** один сайт падает в выдаче — вслед за ним сразу все остальные.

**Причина:** Яндекс и Google анализируют косвенные признаки сети:
один IP-блок, один счётчик Метрики на всех сайтах, одинаковый шаблон,
одинаковые контакты, favicon, мета-теги. При детекции теряется вся сетка разом.

**Митигация:**
- B0.1: уникальный `PUBLIC_METRIKA_ID` для каждого сайта (обязательно до деплоя)
- B0.2: уникальные контакты (телефон, email, адрес) через env-переменные
- B3: разные темы (цвета, шрифты, layout) для разных кластеров сайтов
- B2: разные хостинг-аккаунты / подсети IP для каждого кластера (5-10 сайтов)
- Разные sub-ID в UTM-параметрах партнёрских ссылок

### A3 🟡 Thin content и дублирование

**Симптом:** страницы индексируются, но вытесняются из топа через 1-2 месяца.

**Причина:** все сайты клонируют одного донора → Google/Яндекс видят
дублированный контент. Шаблонный аудит выявил 3 thin_content страницы,
50 quiz_calculator (обычно короткие), 50 service_catalog (описания без тела).

**Митигация:**
- B1.4: второй донор из другой ниши — разный контент на разных сайтах
- Canonical настроен правильно (уже есть в `seo.ts`)
- Страницы с `content_text_chars < 300` (QA warning) — кандидаты на обогащение
  или исключение из индексации через `noindex`

### A4 🟡 Контент устаревает без обновлений

**Симптом:** позиции постепенно падают через 3-4 месяца после индексации.

**Причина:** статический контент, скраплен один раз, никогда не обновляется.
Поисковики отдают предпочтение свежему контенту, особенно в быстроменяющихся нишах.

**Митигация:**
- B7.3: периодический re-crawl донора (раз в 1-2 месяца) через Firecrawl
- Добавлять `dateModified` в JSON-LD при каждом пересборке страницы
- Приоритет: страницы с высоким трафиком re-crawl чаще

## Группа B — Монетизационные риски (трафик есть, денег нет)

### B1 🔴 Нишевый мисматч — контент не конвертируется

**Симптом:** трафик растёт, клики на PromoSlot есть, конверсий нет.

**Причина:** mosseo.ru — SEO-агентство. Аудитория — предприниматели, маркетологи.
Стандартные CPA-офферы (нутра, дейтинг, WOW-товары) не совпадают с этой аудиторией.
Финансовые офферы (кредиты, инвестиции) — потенциально подходят, но конкуренция высокая.

**Митигация:**
- При выборе второго донора (B1.4) сначала выбрать нишу под доступные офферы,
  потом искать донора в этой нише, а не наоборот
- Для mosseo-контента тестировать: B2B-сервисы (CRM, хостинг, домены),
  edu-офферы (курсы по маркетингу), финансы для бизнеса
- Метрика целей (B6.3) покажет реальный CTR по PromoSlot — данные для решения

### B2 🔴 Монетизация не подключена до получения трафика

**Симптом:** трафик пришёл, но некуда монетизировать — PromoSlot пустой,
форма не работает, `/go/` не реализован.

**Причина:** технический долг — монетизационный слой запланирован на B6,
но B6 стоит после B1-B5 в очереди.

**Митигация:**
- B6.1 и B6.3 выполнять **параллельно с B2**, не ждать конца трека B
- Минимальная монетизация: прямые партнёрские ссылки в `links.json`
  без `/go/` редиректа — как временная мера на период B4-B5

### B3 🟡 Форма не работает — лиды не собираются

**Симптом:** пользователи заполняют форму, данные пропадают.

**Причина:** ContactLayout содержит HTML-форму без backend. `action=""` пустой.

**Митигация:**
- B6.4: Formspree (бесплатно до 50 заявок/мес) — 10 минут на подключение
- Это должно быть сделано **до первого деплоя на продакшн**

## Группа C — Операционные риски (не можем масштабировать / управлять)

### C1 🟡 Нет мониторинга — не знаем о проблемах

**Симптом:** сайт упал, позиции рухнули — узнаём через неделю случайно.

**Причина:** нет uptime-мониторинга, нет алертов при падении трафика.

**Митигация:**
- B7.2: UptimeRobot (бесплатно, 5-минутные проверки) на каждый сайт
- Метрика: настроить алерт при падении трафика > 30% за день
- B5.3: Playwright smoke-тесты после каждого деплоя (уже в роадмапе)

### C2 🟡 Ручное управление не масштабируется

**Симптом:** при 10+ сайтах каждый деплой занимает часы, ошибки растут.

**Причина:** B2 (batch deploy) ещё не реализован.

**Митигация:**
- B2 — приоритетная задача после B1.4 (первый тестовый прогон)
- Filesystem MCP используется для аудита конфигов всех сайтов

### C3 🟢 Экономика не сходится на малом объёме

**Симптом:** тратим $50-100/мес на инфраструктуру, зарабатываем меньше.

**Причина:** Keitaro + VPS + домены + хостинги стоят денег,
а CPA-доход при малом трафике не покрывает расходы.

**Unit-экономика:**
- Минимальная точка безубыточности: ~500 уник/день на сайт при CTR 2% и CPL $5 = $50/мес
- При 10 сайтах и общем трафике 5000 уник/день — выход в плюс реален
- Keitaro подключать только после достижения этого порога

**Митигация:**
- Не запускать Keitaro (B6.5) до наличия стабильного трафика
- Первые 2-3 месяца: только прямые ссылки через `/go/` + Formspree
- Считать ROAS каждые 2 недели: доход / расход на инфраструктуру

## Чеклист перед деплоем каждого нового сайта

Перед тем как деплоить очередной сайт в сетку, убедиться:

- [ ] `PUBLIC_METRIKA_ID` — уникальный счётчик Метрики (не тот же, что у других сайтов)
- [ ] `PUBLIC_COMPANY_PHONE`, `PUBLIC_COMPANY_EMAIL` — уникальные контакты
- [ ] `PUBLIC_SITE_NAME`, `PUBLIC_SITE_NAME_FULL` — уникальный бренд
- [ ] Тема отличается от соседних сайтов в том же кластере (B3)
- [ ] Форма обратной связи отправляет (Formspree или аналог настроен)
- [ ] Хотя бы 3-5 крауд-ссылок запланировано после индексации
- [ ] PromoSlot содержит реальный CPA-оффер, соответствующий нише сайта
- [ ] Smoke-тест (Playwright): главная, услуги, контакты — отдают 200

## Приоритет устранения рисков

```
Немедленно (до первого деплоя продакшн):
  A2 — уникальная Метрика и контакты (B0)
  B3 — форма (Formspree, 10 минут)

Параллельно с B1-B2:
  B2 — минимальная монетизация (прямые CPA-ссылки)
  A1 — базовая ссылочная стратегия (B7.1)

После первых данных по трафику:
  B1 — анализ конверсий PromoSlot → смена офферов если нужно
  C1 — UptimeRobot мониторинг (B7.2)
  C3 — расчёт unit-экономики перед запуском Keitaro
```
