# Launch Checklist

## Deployment / Beget

- [ ] SSH access to Beget is configured locally.
- [ ] Deploy credentials are not stored in the repository.
- [ ] Deploy target path on Beget is confirmed.
- [ ] Static build output directory is confirmed.
- [ ] Deploy script supports repeatable upload via SSH/SFTP/rsync.
- [ ] Dry-run or staging deploy is available, if hosting setup allows it.
- [ ] Production deploy preserves expected file permissions.

## Generated Site

- [ ] Pages are generated from `site_pipeline/output/build_manifest.json`.
- [ ] Excluded pages from `site_pipeline/output/excluded_pages.json` are not generated.
- [ ] Redirects from `site_pipeline/output/redirects.json` are configured.
- [ ] Original URL paths are preserved.
- [ ] Representative page types render correctly:
  - [ ] article/blog page
  - [ ] archive page
  - [ ] FAQ page
  - [ ] portfolio page
  - [ ] service page
  - [ ] service catalog/category page
  - [ ] calculator-style service landing page
  - [ ] root/home page
- [ ] `site_pipeline/audit_page_templates.py` has been run after the latest crawl.
- [ ] `template_audit.csv` has been spot-checked for unexpected short pages.

## SEO

- [ ] `title` is present and unique enough on generated pages.
- [ ] `meta description` is present where source data has it.
- [ ] One primary H1 exists per content page where appropriate.
- [ ] Canonical URLs are correct.
- [ ] `sitemap.xml` is generated from buildable pages.
- [ ] `robots.txt` is generated and references sitemap.
- [ ] Internal links are valid or intentionally redirected.
- [ ] Image URLs render or are intentionally proxied/copied.
- [ ] No generated pages use excluded external redirect content.
- [ ] JSON-LD is generated by shared helpers, not manually per template.
- [ ] `Organization` and `WebSite` schema exist where appropriate.
- [ ] Contact page has `ContactPage` / organization contact schema using only reliable data.
- [ ] Articles/blog pages have `Article` or `BlogPosting` schema.
- [ ] FAQ schema is used only on real question/answer pages.
- [ ] Service pages have `Service` schema.
- [ ] Archive pages have `CollectionPage` / `ItemList` where list data is reliable.
- [ ] Portfolio/case pages use a suitable `CreativeWork`-style schema.
- [ ] Representative JSON-LD output is validated before launch.

## Template Architecture

- [ ] Content JSON is not edited for design-only changes.
- [ ] Page type mapping is centralized by path/section.
- [ ] Layouts exist for home, article, archive, service, portfolio, contact, FAQ, and generic pages.
- [ ] SEO/meta/schema helpers are shared across layouts.
- [ ] Theme/design tokens are centralized.
- [ ] A redesign can be done by changing layouts/components/theme files without re-parsing content.

## Affiliate / Partner Links

- [ ] Partner links are managed from central config/data, not hardcoded in templates.
- [ ] Promo/sponsor slots are managed from central config/data.
- [ ] Links/promos can be targeted by page type, section, path, or exact page ID.
- [ ] Partner links can be disabled or replaced quickly.
- [ ] UTM parameters are generated centrally.
- [ ] Paid/sponsored/affiliate outbound links use `rel="sponsored nofollow"` by default.
- [ ] Outbound monetization links are auditable before launch.
- [ ] Sponsor copy is visible to users and not hidden/cloaked.
- [ ] Analytics does not leak sensitive form data through affiliate URLs.

## Analytics

- [ ] Yandex Metrica counter ID is configured.
- [ ] Google Analytics / GA4 ID is configured if required.
- [ ] Analytics scripts are injected once per page.
- [ ] Analytics can be disabled in local development.
- [ ] Production pages load analytics without blocking content rendering.

## Forms / Anti-Spam

- [ ] Feedback/contact form locations are defined.
- [ ] Form delivery method is chosen: Beget PHP/mail, SMTP, external service, or backend endpoint.
- [ ] Form secrets are not committed.
- [ ] Honeypot field or equivalent lightweight anti-spam is enabled.
- [ ] CSRF protection is enabled if using a backend session/form endpoint.
- [ ] Captcha/turnstile is added only if needed.
- [ ] Form success and error states are tested.
- [ ] Submitted data does not expose sensitive information in logs.

## Security / Operations

- [ ] No API keys, passwords, SSH keys, or deploy secrets are committed.
- [ ] Proxy settings, if used, are approved infrastructure only.
- [ ] Build/deploy commands are documented.
- [ ] Rollback path is documented.
- [ ] Final browser smoke test passes after Beget deployment.
