# Traffic Arbitrage Strategy

Этот документ описывает монетизационный слой PBN-фабрики: как трафик с SEO-сайтов
превращается в доход. Читать после `AGENTS.md` и `ROADMAP.md`.

---

## Концепция в одном абзаце

PBN-сайты ранжируются в Яндексе и Google по информационным и коммерческим запросам.
Органический трафик приходит бесплатно. Монетизация — через партнёрские ссылки (CPA),
лидогенерацию (форма) и в перспективе трекер (Keitaro) для умной ротации офферов.
Клоакинг контента не нужен: у нас белые SEO-сайты, поисковому боту показываем то же,
что живому пользователю.

---

## Схема трафика

```
Яндекс / Google
      ↓  органический поиск
PBN-сайт (SEO-контент)
      ↓  PromoSlot / CTA-блок
/go/{offer}/?utm_source=site&utm_medium=promo&utm_campaign={page}
      ↓  (в будущем: Keitaro TDS)
CPA-оффер партнёрки  →  конверсия  →  выплата
```

Параллельно:
```
PBN-сайт → форма обратной связи → лид → продажа / перепродажа
```

## Монетизация — варианты

### 1. CPA прямые ссылки (старт, рекомендуется)

Самый быстрый путь: добавить партнёрские ссылки в PromoSlot и CTA-блоки.
Нет минимального трафика, нет модерации сайта.

**Как работает:**
- Регистрируемся в CPA-сети (Admitad, Offerrum и др.)
- Получаем партнёрскую ссылку на оффер
- Помещаем в `links.json` → PromoSlot вставляет в нужные страницы
- `/go/` редирект добавляет UTM и пишет клик в аналитику
- Конверсия фиксируется в кабинете партнёрки

**Плюсы:** немедленный старт, высокий CPL по финансовым и edu-офферам
**Минусы:** нет собственной статистики конверсий без трекера

### 2. Лидогенерация через форму

Форма обратной связи на страницах услуг и контактов. Лид = заявка от пользователя.
Лиды можно продавать напрямую или через CPA-сети с оплатой за лид.

**Статус:** ContactLayout есть, форма нарисована, но не отправляет.
**Нужно:** Beget PHP-скрипт или внешний сервис (FormSpark, Formspree, n8n).

### 3. Яндекс РСЯ / Google AdSense (позже)

Контекстная реклама на страницах сайта.

**Требования РСЯ (2025):**
- Минимум ~300 уник/день для подачи заявки
- Реально одобряют при ~10 000 уник/день
- Строгая модерация: PBN-сайты с thin content рискуют отказом
- Доход в РСЯ ниже, чем в Google AdSense

**Вывод:** подключать только после набора трафика и только для сайтов
с достаточно богатым контентом. На старте — не приоритет.

### 4. Прямые партнёрства

После набора трафика — прямые договоры с рекламодателями без комиссии сети.
Требует объём и переговоры. Долгосрочная цель.

## /go/ редирект — паттерн

Все партнёрские ссылки идут через собственный редирект, а не напрямую.

```
/go/admitad-aliexpress/  →  302  →  https://aliexpress.com/?partner=XXX&utm_...
/go/tbank-credit/        →  302  →  https://tinkoff.ru/credit/?...
```

**Зачем:**
1. Скрывает партнёрский ID от пользователя (меньше обрезаний UTM)
2. Позволяет поменять ссылку в одном месте (links.json) без деплоя
3. Клик фиксируется в Метрике как цель "outbound_click"
4. Keitaro можно воткнуть между `/go/` и конечным URL позднее

**Реализация в Astro:**
- Статические редиректы через `astro.config.mjs` redirects (только при known URLs)
- Или edge-функция `/src/pages/go/[offer].astro` с `Astro.redirect()`
- `/go/` страницы не индексируются (meta robots noindex или X-Robots-Tag)

## Трекер — Keitaro (B6.5, второй этап)

Keitaro — self-hosted TDS. Устанавливается на отдельный VPS (не на Beget),
принимает клик с нашего `/go/`, логирует параметры, редиректит на оффер.

**Что даёт:**
- Статистика по гео, устройству, источнику, времени суток
- Умная ротация: автоматически отправляет трафик на оффер с лучшим CR
- Постбэки из CPA-сетей — видим конверсии внутри трекера, не только в кабинете сети
- Можно A/B тестировать разные офферы на одном и том же трафике
- Фильтрация ботов (встроенная база, обновляется каждые 2 недели)

**Цена:** ~$25/мес + VPS ~$10-30/мес = $35-55/мес итого

**Когда подключать:** когда есть стабильный трафик и 2+ оффера для ротации.
На старте — излишне, достаточно прямых ссылок через `/go/`.

**Схема с Keitaro:**
```
/go/{offer}/  →  Keitaro (VPS)  →  CPA-оффер
                     ↑
              постбэк от партнёрки (конверсия засчитана)
```

## Клоакинг — решение

**Для SEO-органики (наш случай): не нужен.**

Классический клоакинг (показывать боту одно, юзеру другое) — это риск:
- Google Aug 2025 специально ударил по детекции клоакинга
- Падение трафика 50-95% за 72 часа при детекции
- Восстановление 6-18 месяцев

**Что допустимо и полезно (не клоакинг):**
- Разные PromoSlot по гео (JS на клиенте) — показываем московский оффер москвичам
- Разные офферы по типу устройства — мобильным другой лендинг
- Это легально, не нарушает правила поисковиков

Всё это реализуется через Keitaro (он принимает параметры и перенаправляет)
или через простую JS-логику в PromoSlot.

## Аналитика и цели

Без целей непонятно что конвертирует. Минимальный набор целей в Яндекс.Метрике:

| Цель | Триггер | Как настроить |
|---|---|---|
| `outbound_click` | Клик на `/go/*` | JavaScript event при клике |
| `form_submit` | Отправка формы | Редирект на `/thanks/` или JS event |
| `phone_click` | Клик на номер телефона | JS event на `<a href="tel:">` |
| `cta_click` | Клик на главный CTA | JS event на `.cta-btn` |

Счётчик Метрики уже предусмотрен в `siteConfig.ts`. Цели настраиваются
в интерфейсе Метрики, триггеры добавляем в BaseLayout или отдельный скрипт.

## Footprint и изоляция сети

Яндекс умеет детектировать сети сайтов по косвенным признакам:

| Признак | Риск | Решение |
|---|---|---|
| Один счётчик Метрики на всех сайтах | Высокий | Отдельный счётчик для каждого сайта |
| Один IP / хостинг-аккаунт | Средний | Разные Beget-аккаунты или хостинги для кластеров |
| Одинаковый HTML-шаблон | Средний | B3 (темы) — разные цвета, шрифты, layout |
| Одинаковые контакты | Высокий | Разные телефоны/email через env-переменные |
| Одинаковые партнёрские ссылки | Средний | Разные sub-ID в UTM, разные `/go/` пути |

**В env-переменных каждого сайта должны быть уникальные:**
- `PUBLIC_METRIKA_ID` — свой счётчик
- `PUBLIC_COMPANY_PHONE`, `PUBLIC_COMPANY_EMAIL` — своя контактная информация
- `PUBLIC_SITE_NAME` — свой бренд

## Что нужно построить (B6 задачи)

### B6.1 — `/go/` редирект-обёртка

Файл `site/src/pages/go/[offer].astro`:
```astro
---
import { links } from '../../data/links';
const { offer } = Astro.params;
const target = links[offer];
if (!target) return Astro.redirect('/404/');
return Astro.redirect(target.url + buildUtm(target, Astro.url), 302);
---
```
Ссылки хранятся в `site/src/data/links.ts` (читает из `links.json`).

### B6.2 — PromoSlot из links.json

PromoSlot сейчас использует хардкод. После B4.2 он читает `links.json`.
B6.2 расширяет это: PromoSlot принимает `section` и `pageType`, выбирает
оффер по приоритету секции.

### B6.3 — Цели Метрики

Скрипт `site/src/components/MetrikaGoals.astro` — подключается в BaseLayout,
вешает обработчики на `/go/` клики, форму, телефон.

### B6.4 — Рабочая форма

Вариант 1 (быстро): Formspree — просто меняем `action=""` формы.
Вариант 2 (своё): PHP-скрипт `mail.php` на Beget, деплоится рядом со статикой.
Вариант 3 (гибко): n8n / Make webhook → Telegram-уведомление о лиде.

### B6.5 — Keitaro

Отдельный VPS (~$10/мес), установка одной командой.
`/go/` в Astro редиректит на Keitaro, Keitaro — на оффер.
Постбэки из Admitad/Offerrum настраиваются в кабинете Keitaro.

---

## Порядок реализации B6

```
B6.1 (редирект /go/)           ← можно делать параллельно с B4
     ↓
B6.2 (PromoSlot из links.json) ← зависит от B4.2
     ↓
B6.3 (цели Метрики)            ← можно делать параллельно с B6.2
     ↓
B6.4 (форма)                   ← независимо, в любой момент
     ↓
B6.5 (Keitaro)                 ← когда есть стабильный трафик
```
